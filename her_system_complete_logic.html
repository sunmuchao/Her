📦 一、系统架构概览

前端（React + TypeScript）
↓ HTTP/JSON
后端API网关（FastAPI）
↓ 调用
搜索服务层（partner_search + match_domain）
↓ 读写
Milvus向量库 + MySQL结构化数据
核心设计理念：
  • 双存储架构：Milvus向量库（语义搜索）+ MySQL结构化数据（硬筛选）
  • 时间衰减机制：向量数据支持智能时间衰减，保证数据时效性
  • 溯源机制：所有画像变更都有完整的溯源记录（session_id, evidence_text）
  • 异步处理：画像提取使用后台线程，不阻塞主流程

排序筛选
文件：partner_search/search_ranking.py
- 按评分排序：result_sort_key()

返回JSON响应
包含候选人列表、推荐理由、匹配度评分等

2.4 向量库查询详解

class VectorStore: def search_similar_users( self, user_vector: list[float], # 查询向量（768维） vector_type: str, # personality_traits, values, face_embedding等 top_k: int = 50, similarity_threshold: float = 0.85, exclude_user_ids: list[int] | None = None, ) -> list[dict[str, Any]]: """ 返回: [ { "user_id": int, "similarity": float, # 衰减后的相似度 "original_similarity": float, "version": int, "age_days": float, "decay_factor": float, "decay_config": {...} } ] """

向量类型配置（时间衰减）

时间衰减机制（核心设计）
向量搜索会应用时间衰减因子，确保数据时效性：
- 衰减公式：adjusted_similarity = original_similarity × decay_factor
- 线性衰减：decay_factor = max(min_factor, 1 - age_days/decay_days)
- 指数衰减：decay_factor = max(min_factor, exp(-age_days/decay_days))
向量类型 描述 衰减周期 衰减曲线 最低权重
personality_traits 性格特质（温柔、内向、开朗） 365天 指数衰减 0.7
values 价值观（重视家庭、重视事业） 365天 线性衰减 0.7
life_attitude 生活态度（追求稳定、重视生活质量） 90天 指数衰减 0.5
partner_expectation 择偶期望（希望找个温柔的人） 90天 指数衰减 0.5
emotional_needs 情感需求（需要理解和支持） 30天 线性衰减 0.5
face_embedding 人脸向量 365天 指数衰减 0.9

向量版本管理机制

版本管理流程
1. 查询当前版本号：current_version = get_current_vector_version(user_id, vector_type)
2. 版本号递增：new_version = current_version + 1
3. 软删除旧版本：deactivate_old_vectors(user_id, vector_type)，设置 is_active = false
4. 插入新版本：插入新向量，is_active = true

✨ 七、系统设计亮点

🤖 Agent Native 架构（核心）

Agent 动态理解用户意图，非硬编码规则表。符合 AI Native 原则：AI 是决策大脑，不是规则执行器

🎯 多触发源支持

支持聊天内容、照片上传、视频认证等多种触发方式，全方位收集画像信息

🧠 智能分流

自动区分可量化字段和不可量化字段，分别处理，提高效率

📦 向量版本管理

支持向量版本控制和软删除机制，确保数据一致性

🔍 溯源机制

所有画像变更都有完整的溯源记录（session_id, evidence_text），可追溯

⚡ 异步处理

使用后台线程处理画像提取，不阻塞主流程，提升用户体验

💰 成本优化

批量处理向量生成，节省LLM调用成本

⏰ 时间衰减

向量搜索支持智能时间衰减，保证数据时效性

🎨 三层评分机制

照片搜索采用三层评分（基础分 + 全局加分 + 个性化加分），推荐更精准

🚀 增量处理机制

基于processed_at字段实现增量处理，避免重复处理已处理的聊天记录，提升效率

🛡️ 摘要质检拦截

自动拦截抽象词汇（如"合拍"、"真诚"）和泛化表述，只保留具体描述，提升数据质量

🧹 清空临时条件

会话结束后自动清空working_criteria，避免下次搜索误用旧条件

📊 向量软删除

使用is_active字段实现软删除，保留历史版本，支持数据回溯和审计

2026-07-15：删除硬编码意图识别，全面转向 Agent Native

删除的内容：
1. detect_photo_preference_intent() 函数：硬编码规则表（~140行）
2. _infer_image_understanding() 辅助函数：硬编码图片理解逻辑（~30行）
3. test_photo_intent_agent.py 测试文件：硬编码规则测试（~200行）
4. mode="auto" API 参数：自动意图识别已废弃

删除原因：
- ❌ 违反 Agent Native 原则：硬编码规则表，不是 AI 动态理解
- ❌ 维护成本高：每增加一个新条件，就要写一个 if 语句
- ❌ 无法理解复杂表达：用户说"我不太喜欢太成熟的"，硬编码规则就懵了
- ❌ 生产环境不使用：前端/Agent 都不会传 mode="auto"

替代方案（Agent Native）：
- ✅ Agent（LLM）自己理解用户意图
- ✅ Agent 根据 SOUL.md 和工具 description 构造参数
- ✅ 支持任意复杂表达，无需硬编码
- ✅ 符合 Agent Native 原则：AI 是决策大脑，不是规则执行器
