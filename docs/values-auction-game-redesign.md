# 价值观拍卖会小游戏化重构方案

> 文档版本: v1.0
> 创建日期: 2026-06-02
> 适用范围: `frontend/her-app` 价值观拍卖会前后端重构
> 目标: 将当前“卡片式测评”重构为“具有拍卖感、取舍感、揭晓感”的轻量小游戏

---

## 1. 为什么要重构

当前版本的问题不是“没有逻辑”，而是“没有游戏感”。

用户现在体验到的是：

1. 打开一个测评卡片
2. 对 12 个抽象特质分配数字
3. 提交
4. 查看结果

这本质上还是问卷，不像一场拍卖。

本次重构要解决的核心问题：

1. 把“抽象价值观词条”改成“可感知的拍品”
2. 把“分配数字”改成“出价、取舍、封盘、揭晓”
3. 把“结果标签”改成“你抢下了怎样的人生”
4. 把双人玩法改成“盲拍对照”，而不是“双人答题”

一句话定义新版本：

`价值观拍卖会 = 用有限筹码争夺你最想要的人生拍品，在取舍中暴露真实价值排序。`

---

## 2. 核心设计原则

### 2.1 用户看到的是“拍品”，不是“价值观标签”

不要直接展示：

- 诚实
- 健康
- 自由
- 善良

要展示：

- 无论发生什么都永远不离不弃的灵魂伴侣
- 全家人身体健康、无病无灾到百岁
- 一生无需为生计奔波，随心所欲环游世界
- 研发出一款攻克绝症的特效药，拯救千万人

原因：

1. 具体场景比抽象词更容易产生画面
2. 具体拍品更容易逼出痛感和取舍
3. “拍卖行拍的是拍品”，不是人格题目

### 2.2 前台玩拍品，后台算价值观

前端展示拍品卡，后端保留隐藏价值映射。

例如：

```json
{
  "lot_id": "soulmate",
  "title": "无论发生什么都永远不离不弃的灵魂伴侣",
  "dimension": "emotion_connection",
  "hidden_values": [
    { "key": "love", "weight": 0.45 },
    { "key": "loyalty", "weight": 0.35 },
    { "key": "security", "weight": 0.20 }
  ]
}
```

这样可以同时满足：

1. 用户体验是游戏
2. 系统输出仍然可用于画像、匹配和解释

### 2.3 拍品之间必须有冲突

如果每个拍品都“正确且美好”，用户会全部都想要，游戏张力就没了。

需要刻意设计冲突对，例如：

- `一家行业内顶尖的百亿市值上市公司` vs `一生无需为生计奔波、随心所欲环游世界`
- `无论发生什么都永远不离不弃的灵魂伴侣` vs `历经苦难后内心绝对的平静与开悟`
- `登顶福布斯富豪榜的至高荣誉` vs `改善全球贫困儿童的教育与生活环境`

用户要在真实欲望与理想价值之间摇摆，游戏才成立。

### 2.4 结果先讲“你拍下了什么”，再讲“你是什么人”

结果页不应该先贴标签。

推荐顺序：

1. 先揭晓 Top3 拍品
2. 再展示“你主动放弃了什么”
3. 最后系统归纳价值观倾向

这样用户会觉得：

`系统理解了我的选择`

而不是：

`系统给我贴了个类型标签`

---

## 3. 新版拍品体系

## 3.1 四大维度

拍品统一分为四大维度：

1. 物质与成就
2. 情感与连接
3. 自我与成长
4. 利他与奉献

这四个维度既完整，又适合视觉上做成四个“展厅”。

## 3.2 拍品数量建议

建议首版使用 20 个拍品：

1. 每个维度 5 个
2. 总量比当前 12 个更像“拍卖池”
3. 仍可在 90 秒到 2 分钟内完成

## 3.3 正式拍品库

### A. 物质与成就

## 4. 隐藏价值映射规则

## 4.1 一个拍品不只对应一个价值

每个拍品应支持“主价值 + 次价值”。

例如：

```json
{
  "lot_id": "family_health",
  "title": "全家人身体健康、无病无灾到百岁",
  "dimension": "emotion_connection",
  "hidden_values": [
    { "key": "family", "weight": 0.45 },
    { "key": "security", "weight": 0.35 },
    { "key": "care", "weight": 0.20 }
  ]
}
```

## 4.2 推荐底层价值字典

建议统一到以下隐藏值上：

- `wealth`
- `status`
- `power`
- `freedom`
- `security`
- `love`
- `loyalty`
- `family`
- `friendship`
- `companionship`
- `recognition`
- `self_actualization`
- `wisdom`
- `inner_peace`
- `independence`
- `altruism`
- `social_responsibility`
- `meaning`

## 4.3 结果计算逻辑

用户出价后，系统做两层计算：

1. 拍品层：哪些拍品被抢下
2. 价值层：这些拍品在隐藏价值上形成了怎样的权重分布

示例：

- `soulmate` 5 票
- `family_health` 3 票
- `absolute_favor` 2 票

隐藏层可能累加出：

- `security`: 0.31
- `love`: 0.24
- `family`: 0.18
- `loyalty`: 0.16
- `companionship`: 0.11

最终系统可以说：

`你表面上拍下的是“灵魂伴侣”和“家人平安”，底层真正强势的是安全感与被坚定选择。`

## 5. 单人玩法流程

## 5.1 核心节奏

单人流程建议拆成五幕：

1. 入场
2. 首轮抢拍
3. 取舍加压
4. 封盘确认
5. 揭晓与解读

## 5.2 详细流程

### 第一幕：入场

目标：建立“我进入了一场拍卖”的心理预期。

页面元素：

1. 标题：`今晚，你只能拍下 10 枚筹码 worth 的人生`
2. 提示：`20 件拍品，10 枚筹码，不可能全都要`
3. 展示 10 枚实体感筹码
4. CTA：`进入拍卖场`

不要在这一屏解释太多规则。

### 第二幕：首轮抢拍

目标：让用户真的开始“投筹码”，而不是“填数字”。

交互建议：

1. 20 张拍品卡按 4 大展厅分区
2. 用户点开拍品卡后，可以：
   - `出 1 枚`
   - 长按连投
   - 或拖拽筹码到拍品卡
3. 每次投出时做轻反馈：
   - 筹码飞向拍品
   - 顶部余额减 1
   - 拍品卡亮度上升

### 第三幕：取舍加压

当用户只剩下少量筹码时，系统开始强化选择成本。

推荐阈值：

1. 剩余 5 枚时：轻提醒
2. 剩余 3 枚时：强化取舍提示
3. 剩余 1 枚时：进入封盘前紧张状态

示例文案：

1. `你只剩 3 枚筹码了`
2. `还想保住自由，也不愿放弃灵魂伴侣？`
3. `再给“百亿上市公司”加 1 枚，就等于放弃“温暖的家”`

### 第四幕：封盘确认

不要使用“提交”这个词。

改成：

- `封盘`
- `锁定出价`
- `准备揭晓`

封盘页展示：

1. 你当前最高的 3 个拍品
2. 你一票未出的拍品
3. 一句主持人口吻文案：
   `这就是你今晚真正舍不得放掉的人生。`

CTA：`封盘揭晓`

### 第五幕：揭晓与解读

结果页不要一次性平铺。

建议采用三段揭晓：

1. 第 3 名拍品翻牌
2. 第 2 名拍品翻牌
3. 第 1 名压轴拍品翻牌

然后再出现：

1. 你的主倾向总结
2. 被你主动放弃的世界
3. 相处建议 / 择偶建议

## 6. 双人玩法流程

## 6.1 双人玩法定义

双人版不叫“双人答题”，而叫：

`盲拍对照`

文案建议：

`你和 TA 各自秘密出价，封盘后同时揭晓。`

## 6.2 双人流程

### 第一步：发起邀请

邀请文案：

`来一场盲拍吧，看看你们抢的是不是同一种人生。`

### 第二步：同时入场

两个人进入同一场 session，但彼此完全不可见。

必须明确告诉用户：

1. 你看不到对方出价
2. 对方也看不到你
3. 双方都封盘后才会同时揭晓

### 第三步：各自拍卖

交互与单人一致，但顶部提示改成：

`这是秘密出价，封盘前没人知道你抢了什么。`

### 第四步：等待对方封盘

等待页不应该只是技术状态页。

要像主持人报幕：

1. `你的拍品已锁定`
2. `对方仍在出价中`
3. `封盘后将同时揭晓：共鸣点、分歧点、最危险的冲突`

### 第五步：同时揭晓

展示顺序建议：

1. 先揭晓“你拍下了什么”
2. 再揭晓“TA拍下了什么”
3. 再展示“你们共同抢下的东西”
4. 最后高亮“你最看重的，TA几乎没出价”

这比直接给一个“匹配分析卡”更有冲击力。

## 7. 结果解释体系

## 7.1 结果页结构

结果解释按以下顺序组织：

1. 你拍下的 Top3 拍品
2. 你放弃的拍品类型
3. 你底层最强的价值排序
4. 你在关系里最容易追求什么
5. 你最容易在哪类人身上受伤

## 7.2 单人解释模板

不要先说：

`你是忠诚至上型`

先说：

`你最想抢下的，不是热闹，也不是名声，而是一个不会离开你的人。`

然后再补：

`从你的出价看，你底层更偏向安全感、被坚定选择和长期稳定。`

## 7.3 双人解释模板

双人解释不需要给分数优先。

应优先输出：

1. 共鸣点
2. 错位点
3. 冲突风险
4. 一句可继续聊下去的话题建议

示例：

`你想要的是“永远不离不弃的伴侣”，TA最想要的是“无需为生计奔波的自由人生”。这不一定冲突，但意味着你们对“关系的优先级”理解并不一样。`

## 8. 视觉与动效建议

## 8.1 视觉关键词

推荐方向：

1. 温暖
2. 轻俏皮
3. 综艺主持感
4. 带一点拍卖会的戏剧感

不建议：

1. 心理测试风
2. 表单风
3. 赛博朋克风
4. 过度严肃的专业问卷风

## 8.2 组件隐喻

建议重点强化三个对象：

1. `筹码`
2. `拍品卡`
3. `封盘章`

而不是强化滑块、数字输入器。

## 8.3 动效原则

遵循：

1. 只在关键节点动
2. 优先使用 `transform` 和 `opacity`
3. 单次动效控制在 150-300ms
4. 尊重 `prefers-reduced-motion`

重点动效节点：

1. 筹码飞入拍品卡
2. 剩余筹码警报
3. 封盘
4. Top3 逐个翻牌
5. 双人同步揭晓

## 9. 与当前实现的关系

## 9.1 后端接口基本可复用

当前接口层不需要推翻：

- `POST /v1/values-auction/start`
- `POST /v1/values-auction/traits`
- `POST /v1/values-auction/submit`
- `POST /v1/values-auction/interpretation`
- `POST /v1/values-auction/start-together`
- `POST /v1/values-auction/submit-together`
- `POST /v1/values-auction/check-status`
- `POST /v1/values-auction/reuse-together`

需要变的是返回数据结构和前端呈现方式：

1. `traits` 不再只返回抽象特质，而返回拍品卡
2. `submit` 不再只返回排序结果，而返回揭晓所需数据
3. `interpretation` 从“价值观标签解读”升级为“拍品选择解读”

## 9.2 当前最需要重做的前端组件

优先级从高到低：

1. `ValuesAuctionBiddingCard.tsx`
   现状像表单，需改为“拍卖棋盘 + 筹码池 + 封盘区”

2. `ValuesAuctionResultCard.tsx`
   现状像静态结果卡，需改为“Top3 分步揭晓”

3. `ValuesAuctionWaitingCard.tsx`
   现状像轮询等待页，需改为“等待对手封盘”

4. `ValuesMatchAnalysisCard.tsx`
   现状像普通分析面板，需改为“双方盲拍对照揭晓”

## 9.3 数据模型演进建议

当前 `trait_id` 体系建议演进为 `lot_id` 体系。

例如：

```json
{
  "lot_id": "soulmate",
  "title": "无论发生什么都永远不离不弃的灵魂伴侣",
  "dimension": "emotion_connection",
  "chips": 4,
  "rank": 1,
  "hidden_values": [
    { "key": "love", "weight": 0.45 },
    { "key": "loyalty", "weight": 0.35 },
    { "key": "security", "weight": 0.20 }
  ]
}
```

保持兼容方式：

1. 前台全部改读 `lot_id/title/dimension`
2. 后台仍可落画像到统一的隐藏价值字典

## 10. MVP 重构顺序

如果按最小代价落地，建议分三期。

### Phase 1: 文案与拍品替换

目标：先把“抽象测评感”去掉。

做法：

1. 用 20 个拍品替换 12 个抽象 trait
2. 结果页改为“你拍下了什么”
3. 保留现有卡片结构和接口时序

### Phase 2: 交互小游戏化

目标：建立真正的拍卖体验。

做法：

1. 筹码池 + 拍品卡出价
2. 剩余筹码提醒
3. 封盘页
4. 单人揭晓动画

### Phase 3: 双人盲拍升级

目标：把双人模式做成产品亮点。

做法：

1. 重做等待页
2. 重做双人揭晓页
3. 引入“共鸣拍品 / 错位拍品 / 高冲突拍品”

---

## 11. 非目标

本轮重构暂不追求：

1. 复杂实时竞价
2. 多人在线拍卖
3. 完整经济系统
4. 分数排行榜

本轮只追求：

1. 用户觉得自己真的在“拍”
2. 用户觉得自己真的在“舍弃”
3. 用户对结果有情绪反应
4. 双人对照能引发真实讨论

---

## 12. 最终产品定义

重构后的价值观拍卖会，不应该再被用户理解为：

`一个有点花哨的性格测试`

而应该被理解为：

`一场很短、很好玩、但玩完会突然意识到“原来我真正想要的是这个”的关系小游戏。`
