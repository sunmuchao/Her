Page Direction

这版聊天页的核心，不是气泡好不好看，而是风险处理别再脱离聊天上下文。

你的后端已经支持主聊天、红娘私聊、举报、风险提示和见面后反馈，所以前端不能再做成普通单线程 IM。用户一边聊，一边就能看到平台建议和信任状态，才符合现在系统的结构。

主聊天和红娘私聊分开 主聊天面向双方，红娘私聊只对单个用户可见，避免把系统建议误发给对方。
风险提醒常驻顶部 不要把信任状态埋到资料详情页，聊天时用户更需要知道“现在该不该谨慎一点”。
举报与见面反馈留在同一页 用户出事时不会先想起“去设置里找入口”，所以必须就地处理。

后续可接接口

  • `/v2/chat/cases/{case_id}/timeline` 接主聊天和红娘私聊。
  • `/v1/chat/threads/{thread_id}/risk-overview` 接谨慎提示。
  • `/v1/chat/threads/{thread_id}/reports` 接举报。
  • `/v1/chat/threads/{thread_id}/meeting-feedback` 接见面后反馈。

第二版可以再加

  • 会话列表页，展示多个 case 的阶段状态。
  • 聊天内“建议回复草稿”但不强推自动发送。
  • 顶部信任条点开后进入完整 `trust-hub`。
  • 风险触发后直接弹出补认证或申诉引导。
