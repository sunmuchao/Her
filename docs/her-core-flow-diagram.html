Her 系统核心逻辑流程图

基于当前代码仓库实现梳理。Her 是「关系运营 / 红娘协作」产品原型， 核心主线为：找对象 → 建立连接 → 聊天。 认证、风控、画像、运营任务等作为支撑域，负责放行、拦截、校验与辅助决策。

2 核心主链路全景

用户从登录入驻开始，经发现/搜索/推荐找到对象，通过撮合建立双边连接，最终进入聊天与关系维护。 各阶段由独立子系统负责，通过 match_domain 事件与 outbox 联动。

6 撮合建立连接流程

双边候选池 → edge 汇聚 pair → 满足阈值开 case → 回复推进 → 反馈回流画像。

flowchart TD
  MEMBER["创建/更新 pool member
状态 · case cap · min_pair_score"] --> REFRESH["refresh pool member
生成候选 edge"]
  REFRESH --> EDGE["单向 edge 写入"]
  EDGE --> RECIP{检查 reciprocal edge}
  RECIP -->|双边存在| PAIR["合成 pair
eligible / blocked / stale / cooling"]
  RECIP -->|仅单边| WAIT["等待对向 edge"]

  PAIR --> CHECK{pair 可用?
score ≥ threshold
双方仍在找对象}
  CHECK -->|否| RECYCLE["回收 / 标记 stale"]
  CHECK -->|是| CASE["open case
检查 daily cap · 有效期"]
  CASE --> REPLY["记录 reply 事件
case 状态推进"]
  REPLY --> OUTCOME{结果}
  OUTCOME -->|mutual_accept| ACCEPT["双边接受"]
  OUTCOME -->|关闭| CLOSE["关闭 case"]
  OUTCOME -->|需重验证| REVAL["needs_revalidation"]

  REPLY --> FB["member feedback
+ persona patch"]
  FB --> PM["upsert_persona_memory
→ 影响后续 pair"]

  ACCEPT --> CHAT_FLOW["→ 创建 chat thread / conversation"]

10 核心状态机

match_domain 统一定义跨系统状态枚举，各子系统分层管理推荐/关系/案例状态。

RelationStatus（推荐关系）

  • new → recommended
  • saved / skipped / cooling
  • direct_greet_started
  • proxy_intro_active
  • closed

PairStatus（双边 Pair）

  • eligible → case_opened
  • below_threshold / blocked
  • cooling / stale
  • mutual_accept
  • needs_revalidation

Recommendation Delivery

  • review_pending
  • pending_delivery
  • delivered
  • （与 case_status 分层）

MatchEvent（统一事件）

  • event_type + aggregate
  • actor + source_service
  • correlation / idempotency
  • → outbox 传播
