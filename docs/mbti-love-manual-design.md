### 2.1 EI维度：社交能量 - 第1-5题

#### 第1题：约会后能量状态（已更新）

```
题目：和刚认识的Crush进行了一场长达6小时的完美约会，
      分开上地铁后你的真实状态是？

选项：
A. 兴奋到头皮发麻，立刻在闺蜜/兄弟群发长文复盘，
   顺便发个朋友圈 ── 5分（强E）
B. 在微信上继续跟Crush黏黏糊糊地聊天：
   【到家了吗？今天好开心呀】 ── 4分（E）
C. 感觉挺好，各回各家，看对方怎么发消息再接话 ── 3分（中性）
D. 戴上降噪耳机，开始在手机上玩游戏或刷视频，
   享受属于自己的时间 ── 2分（I）
E. 瞬间闭目养神，感觉今日份的人类社交电量已彻底归零，
   谁也别戳我 ── 1分（强I）

```

## 六、恋爱匹配度计算模型

### 6.1 核心原则

```
EI维度（社交能量）：倾向于【互补】
  - 一个极外向(高E)配一个极内向(低I)是绝配（充电宝与耗电怪）
  - 两个极端E会抢麦，两个极端I会相顾无言

SN维度（关注焦点）：倾向于【绝对同频】
  - 务实派(S)和氛围浪漫派(N)三观难调和，必须同频！

TF维度（决策方式）：倾向于【轻微互补】
  - 一个理智T + 一个感性F 是稳固结构
  - 两个T吵架是辩论赛，两个F吵架是洪水淹没地球

JP维度（生活节奏）：倾向于【中度互补】
  - 一计划(J)一随性(P)最舒服
  - 两个J会因为牙膏怎么挤打架，两个P约会永远在迟到
```

### 6.2 算法伪代码

```python
def calculate_love_match(user_a_scores, user_b_scores):
    match_score = 100.0
    
    # EI维度：互补加分
    ei_diff = abs(user_a_scores['ei'] - user_b_scores['ei'])
    if ei_diff > 50:
        match_score += 5   # 极度互补奖励
    elif ei_diff < 15:
        match_score -= 8   # 同质化扣分
    
    # SN维度：同频加分，冲突扣分
    sn_diff = abs(user_a_scores['sn'] - user_b_scores['sn'])
    if sn_diff > 60:
        match_score -= 15  # 三观冲突扣分
    elif sn_diff < 20:
        match_score += 10  # 灵魂共鸣奖励
    
    # TF维度：一T一F是绝配
    a_is_t = user_a_scores['tf'] >= 50
    b_is_t = user_b_scores['tf'] >= 50
    if a_is_t != b_is_t:
        match_score += 12  # 完美互补
    
    # JP维度：一J一P互补
    a_is_j = user_a_scores['jp'] >= 50
    b_is_j = user_b_scores['jp'] >= 50
    if a_is_j != b_is_j:
        match_score += 8   # 互补加分
    
    return max(0, min(100, match_score))
```

### 6.3 匹配度等级

| 分数 | 等级 | 说明 |
|------|------|------|
| ≥85 | 🌟 天作之合 | 恋爱匹配度极高 |
| 70-84 | 💕 很适合 | 恋爱匹配度良好 |
| 50-69 | ⚖️ 需磨合 | 恋爱匹配度中等 |
| <50 | ⚠️ 需努力 | 恋爱匹配度较低 |

## 七、维度得分计算规则

### 7.1 计算公式

```
每个维度5题，每题5选项（1-5分）

维度得分 = (总分 - 5) / 20 × 100

示例：
EI维度5题得分：5+5+4+5+4 = 23
EI得分 = (23 - 5) / 20 × 100 = 90分

解释：
- ≥70分：该维度高分倾向（如EI≥70 = E型）
- 40-70分：该维度中等倾向
- <40分：该维度低分倾向（如EI<40 = I型）
```

### 7.2 类型判定规则（统一50分分界）

```
EI得分 ≥50 → E（外向）
EI得分 <50 → I（内向）

SN得分 ≥50 → S（实感）
SN得分 <50 → N（直觉）

TF得分 ≥50 → T（思考）
TF得分 <50 → F（情感）

JP得分 ≥50 → J（判断）
JP得分 <50 → P（知觉）

组合示例：
EI=90(E) + SN=25(N) + TF=25(F) + JP=55(J) = ENFJ
```

### 8.4 断点续传机制（防呆设计）

**问题场景**：

```
用户答完第5题 → 看到反馈卡片 → 接电话退出App
下次进来 → 从第1题重新开始 → 用户崩溃 💥
```

**解决方案**：

新增 API `/v1/assessment/get-or-create`，实现断点续传：

```typescript
// 前端调用
void getOrCreateAssessment(userKey).then((intro) => {
  if (intro.resumed) {
    // 有未完成的测评，恢复进度
    console.log(`恢复测评：已答 ${intro.answered_count} 题`)
  } else {
    // 新测评
  }
})
```

**后端逻辑**：

```python
def get_or_create_assessment(user_key):
    # 1. 查找用户最近的未完成测评
    recent_session = 查询数据库(user_key, status="in_progress")

    if recent_session:
        # 2. 未完成，恢复进度
        return {
            "card_type": "assessment_intro",
            "intro_data": {
                "title": "继续上次的测评",
                "description": f"已答 {answered_count} 题，还有 {20 - answered_count} 题",
            },
            "resumed": True,
            "answered_count": 5,
        }

    # 3. 没有未完成的测评，创建新测评
    return start_assessment(user_key)
```

**返回数据对比**：

```json

{
  "card_type": "assessment_intro",
  "intro_data": {
    "title": "MBTI 恋爱说明书",
    "description": "测测你在恋爱里是什么派"
  }
}

// 恢复测评
{
  "card_type": "assessment_intro",
  "intro_data": {
    "title": "继续上次的测评",
    "description": "已答 5 题，还有 15 题"
  },
  "resumed": true,
  "answered_count": 5
}
```
