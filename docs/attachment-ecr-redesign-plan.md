# 依恋风格测评 ECR 化重构方案

> 版本: v1.0
> 日期: 2026-06-04
> 适用范围: 发现页加号入口 `attachment_style`
> 目标: 将现有“相处模式 / 依恋风格”从“四型产品测验”重构为“ECR 底层测量 + Her 风格表达”的正式方案

---

## 一、这次改什么

这次不是简单换题，而是整套依恋风格测评一起换：

- 底层测量逻辑改成 **ECR / ECR-R 思路**
- 题目表达改成 **Her 现在的口语化恋爱语境**
- 结果说明改成 **ECR 结果结构**
- 小雅话术改成 **MBTI 那种能看懂、记得住、但不土的表达**

一句话概括：

**底层按 ECR 测“焦虑”和“回避”，外层仍然说人话，保持现在产品调性。**

---

## 二、为什么要改

现在线上的依恋风格逻辑，本质上是：

- 单独测 `secure`
- 单独测 `anxious`
- 单独测 `avoidant`
- 单独测 `fearful`
- 最后选四个里最高的一个当主类型

这套逻辑的问题不是“不能用”，而是它**不是 ECR**。

ECR 的核心不是四条独立轴，而是两条核心轴：

- `anxiety`：在关系里有多容易不安、怕被忽略、怕被抛下
- `avoidance`：在关系里有多容易退、怕太亲密、怕太被看见

然后再根据这两个维度的高低，解释为：

- 低焦虑 + 低回避：更接近安全
- 高焦虑 + 低回避：更接近焦虑型
- 低焦虑 + 高回避：更接近回避型
- 高焦虑 + 高回避：更接近恐惧回避 / 混乱拉扯

所以这次改造的根本目标是：

- 让测量逻辑回到 ECR
- 让结果解释更稳定、更可信
- 让后续匹配、推荐、画像沉淀也更好用

---

## 三、改造原则

### 3.1 底层学术，外层产品

底层：

- 只测 ECR 两个核心维度
- 计分、归因、结果解释都围绕两维展开

外层：

- 不写学术腔
- 不写论文原句
- 不直接端上“attachment anxiety / avoidance”给普通用户
- 统一翻译成用户能立刻代入的关系表达

### 3.2 保留类型感，但类型不能主导计分

用户还是需要一个“我大概是哪一挂”的认知抓手，所以可以保留：

- 稳定靠近型
- 高敏确认型
- 边界后撤型
- 拉扯矛盾型

但这些标签只能是：

- **结果解释层的二级呈现**

不能再是：

- **题目分组层**
- **底层计分层**

### 3.3 文案风格参考 MBTI，不参考现在 attachment 的毒舌过头版本

建议继承 MBTI 现在线上更成熟的风格：

- 有画面感
- 有记忆点
- 不学术
- 不过度羞辱
- 不把用户固定成人格缺陷

不建议继续用太重的“赛博怨妇 / 装死大师 / 反复横跳狂魔”路线，因为：

- 娱乐性强，但会压过测量本身
- 容易让用户觉得被骂，不像被理解
- 和 ECR 连续维度逻辑不够匹配

### 3.4 结果文案的学术锚点

这次结果内容不再按“产品直觉”自由发挥，而是先锚定 ECR / ECR-R 文献里的稳定结论，再做 Her 风格润色。

本轮结果文案主要依据以下一手或权威学术来源：

- Brennan, Clark, & Shaver (1998)
  核心锚点：成人依恋可稳定落在两条连续维度上，即 `attachment anxiety` 与 `attachment avoidance`。
- Fraley, Waller, & Brennan (2000), ECR-R
  核心锚点：`anxiety` 主要涉及对拒绝、被抛下、伴侣不可得的担心；`avoidance` 主要涉及对亲密、依赖、情绪暴露的不适与回撤。
- Mikulincer & Shaver 系列研究 / 综述
  核心锚点：高焦虑更常见的是放大威胁、持续寻求确认；高回避更常见的是拉开距离、压低依赖和暴露；低焦虑低回避更接近安全依恋下的稳定靠近与互相依靠。

落地原则：

- 可以写“更容易 / 往往 / 倾向于”，不能写成绝对人格宣判。
- 可以写“更在意回应是否稳定”“更容易在亲密过密时后撤”，不能硬写成长经历、创伤来源、隐藏动机。
- `fearful` 象限的描述，明确视为“高焦虑 + 高回避”的组合解释，不额外发明第三套机制。

一句话：

**先按论文定义说清楚，再把语气翻译成现在产品能用的人话。**

## 四、目标结构

### 4.1 底层维度

最终只保留两个正式维度：

- `anxiety`
- `avoidance`

### 4.2 用户可见的翻译名

建议在卡片里用更自然的中文：

| 系统维度 | 用户可见名 | 解释 |
|---|---|---|
| `anxiety` | 关系不安度 | 你会不会因为回应、距离、态度变化而很快慌起来 |
| `avoidance` | 亲密后撤度 | 你会不会在关系太近、太黏、太深入时想往后退 |

不建议直接写：

- 焦虑型分数
- 回避型分数

建议写：

- 关系不安度
- 亲密后撤度

这样更像产品语言，也更容易被普通用户接受。

### 4.3 二级类型标签

结果页可以保留一个“你更偏哪一挂”的标签，但必须明确：

- 它是两维组合后的结果
- 不是四套独立分数选出来的

建议四类命名如下：

| 象限 | 内部组合 | 用户标签 | 一句话说明 |
|---|---|---|---|
| 低焦虑 + 低回避 | secure-ish | 稳定靠近型 | 既不容易慌，也不太会躲 |
| 高焦虑 + 低回避 | anxious-ish | 高敏确认型 | 很想靠近，也特别怕失去回应 |
| 低焦虑 + 高回避 | avoidant-ish | 边界后撤型 | 不一定不在乎，但压力一来先后退 |
| 高焦虑 + 高回避 | fearful-ish | 拉扯矛盾型 | 一边想靠近，一边又怕自己受伤 |

备注：

- `secure-ish / anxious-ish / avoidant-ish / fearful-ish` 只是内部便于沟通
- 对用户优先展示中文标签

### 4.4 结果可视化改成二维坐标，不再用雷达图

如果底层已经改成 ECR 两维，结果页主视觉就不应该继续用雷达图。

原因：

- 雷达图适合多维并列展示
- ECR 的正式结果只有两条轴
- 继续用雷达图会让用户误以为“还是四个独立人格维度”

建议统一替换成：

- **二维坐标图 / 四象限图**

推荐示意：

```text
               ▲ 高关系不安度（怕失去、怕被忽略）
               │
 拉扯矛盾型     │     高敏确认型
 （高焦虑高回避）│    （高焦虑低回避）
               │
◄──────────────┼──────────────► 高亲密后撤度（怕太近、怕被推进太快）
 低亲密后撤度    │
               │
 稳定靠近型     │     边界后撤型
 （低焦虑低回避）│    （低焦虑高回避）
               │
               ▼ 低关系不安度
```

如果要在产品中保留学术别名，可放在弱说明里：

- 稳定靠近型 `Secure`
- 高敏确认型 `Preoccupied`
- 边界后撤型 `Dismissing-Avoidant`
- 拉扯矛盾型 `Fearful-Avoidant`

但主展示优先中文，不建议英文名抢视觉中心。

## 五、题目怎么改

### 5.1 题目设计原则

新的题目不能再按“安全 / 焦虑 / 回避 / 恐惧”分组出题。

应该改为：

- 所有题目都只服务于 `anxiety` 或 `avoidance`
- 每道题只能主要测一个维度
- 然后通过总分得出两个连续结果

### 5.2 推荐题量

推荐两个版本：

#### 方案 A：12 题正式版

- `anxiety` 6 题
- `avoidance` 6 题
- 每题 5 级选项
- 完成时长约 2.5 到 3 分钟

优点：

- 和现在 12 题时长接近
- 改造成本低
- 产品节奏最平滑

#### 方案 B：16 题增强版

- `anxiety` 8 题
- `avoidance` 8 题
- 完成时长约 3 到 4 分钟

优点：

- 稳定性更高
- 文案空间更充分
- 更接近正式量表体验

建议优先：

- **先上 12 题正式版**

理由：

- 用户心智已习惯“依恋风格约 3 分钟”
- 发现页加号入口不适合太长
- 先把结构换对比把题量拉长更重要

### 5.3 题目表达方式

题目应该保留你们现在擅长的：

- 恋爱场景
- 聊天场景
- 距离变化
- 沟通反应
- 关系推进时的真实感受

但不要写成：

- 明显在问“你是不是焦虑型”
- 明显在问“你是不是回避型”
- 强情节、强夸张、强段子

应该写成：

- 用户一看就代入
- 但又能稳定落到 ECR 核心构念上

### 5.4 推荐题目风格示例

以下只是风格样例，不是最终题库。

#### 测 `anxiety` 的题目风格样例

题目例 1：

> 对方回消息比平时慢很多时，你心里更容易出现哪种状态？

选项方向：

- `A` 基本不慌，默认对方只是忙
- `B` 会多看两眼，但还能稳住
- `C` 有点不安，会开始猜是不是哪里不对
- `D` 很容易往“是不是不在乎了”上想
- `E` 脑子已经开始自动跑最坏剧情

题目例 2：

> 当关系变重要之后，你会不会很在意对方有没有持续给你回应？

#### 测 `avoidance` 的题目风格样例

题目例 1：

> 当对方想更频繁见面、聊天、分享情绪时，你通常更接近哪种感觉？

选项方向：

- `A` 会觉得关系在自然靠近
- `B` 可以接受，只是偶尔需要缓一缓
- `C` 会开始感觉有一点压力
- `D` 会本能地想把距离拉开一点
- `E` 一旦太近就想先退开，晚点再说

题目例 2：

> 当别人真的想看见你的脆弱、走进你的内心时，你更容易是什么反应？

### 5.5 不建议再出现的题目问题

以下写法建议避免：

- “你是不是稳如老狗”
- “你会不会立刻冷暴力断联”
- “连分手财产分配都想好了”
- “前一秒结婚后一秒男人没一个好东西”

原因不是不能有网感，而是这些表达：

- 太像段子
- 太像标签
- 不像量表
- 会放大羞耻感和表演感

## 六、计分逻辑怎么改

### 6.1 新计分模型

新逻辑必须改成：

- 每题归属 `anxiety` 或 `avoidance`
- 每题 1 到 5 分
- 维度内求和
- 统一换算成 0 到 100

结果只保留：

- `anxiety_score`
- `avoidance_score`

### 6.2 判型逻辑

有两层结果：

#### 第一层：正式结果

- 输出两个连续分数
- 这是唯一正式测量结果

#### 第二层：辅助标签

根据两个分数做象限解释：

- 低焦虑 + 低回避 -> 稳定靠近型
- 高焦虑 + 低回避 -> 高敏确认型
- 低焦虑 + 高回避 -> 边界后撤型
- 高焦虑 + 高回避 -> 拉扯矛盾型

### 6.3 阈值建议

阈值有两种做法：

#### 做法 A：先用产品阈值

- `< 40` 低
- `40 - 60` 中
- `> 60` 高

优点：

- 简单
- 容易实现
- 和现有产品的高/中/低理解一致

#### 做法 B：后续基于样本重标

等积累样本后：

- 用真实答题分布做分位数校准
- 让“高 / 中 / 低”更贴合产品用户群

建议阶段方案：

- **第一版先用产品阈值**
- **第二版再做样本校准**

### 6.4 不再保留的逻辑

以下逻辑建议彻底删除：

- `secure` 独立计分
- `fearful` 独立计分
- `secure >= 60` 直接判安全型
- 四型分别出题分别打分

## 七、结果卡片怎么改

### 7.1 结果卡片结构

建议结果卡片结构变成：

1. 主标题
2. 二级标签
3. 一句话总结
4. 二维坐标图
5. 两个维度条
6. 核心解释
7. 结果奖励文案

### 7.2 推荐卡片结构示例

```text
测评完成

你这次更偏「高敏确认型」

你不是不独立，你只是很在意关系里的回应有没有持续出现。

象限位置：高关系不安度 + 低亲密后撤度

关系不安度：78
亲密后撤度：29

当对方忽冷忽热、回应变少、态度不明时，
你会比很多人更快感觉到慌。
但你并不想退，你反而会更想确认这段关系到底还稳不稳。
```

### 7.3 维度条命名

当前维度行建议改为：

- `关系不安度`
- `亲密后撤度`

level 可继续保留：

- `高`
- `中`
- `低`

但 trait 不能再是：

- 黏人精认证
- 冷暴力大师

建议改为更稳的产品表达：

| 维度 | 高 | 中 | 低 |
|---|---|---|---|
| 关系不安度 | 回应敏感 | 容易牵动 | 稳定感较强 |
| 亲密后撤度 | 边界警觉 | 慢热靠近 | 靠近自如 |

### 7.4 二维坐标图展示建议

建议前端在结果页主视觉展示一个简洁的二维象限图：

- 纵轴：`关系不安度`
- 横轴：`亲密后撤度`
- 用户位置：一个高亮点
- 当前象限：轻微底色强调
- 四个角落：放四种中文标签

展示原则：

- 不做论文图风格
- 不做复杂刻度图
- 不把解释文字全塞进图里

应该做到：

- 用户一眼看懂自己更容易“慌”还是更容易“退”
- 用户一眼看懂自己更靠近哪种相处模式

### 7.5 二维坐标图命名建议

主视觉建议使用产品化命名：

- 纵轴：`关系不安度`
- 横轴：`亲密后撤度`

可在次级说明里补学术对应：

- 关系不安度 = attachment anxiety
- 亲密后撤度 = attachment avoidance

不建议主图直接把轴标题写成：

- 高依恋焦虑
- 高依恋回避

因为这会明显削弱产品可读性。

### 7.6 结果 summary 的新写法

summary 不再写：

- 你在恋爱里很稳
- 你是某某型

建议写成两维翻译句：

- 你对关系变化比较敏感，但不太会主动后退
- 你不算容易慌，但一旦关系太近，会更需要空间
- 你既容易被关系牵动，也容易在压力大时先往后退

这样更贴近 ECR。

## 八、结果说明文案怎么改

### 8.1 结果说明模块建议

现有解释模块可以保留结构感，但内容必须换成 ECR 逻辑。

建议卡片内容模块为：

- `你的关系驱动力`
- `你会在哪些时刻最容易被触发`
- `你靠什么重新稳定下来`
- `你在关系里的常见误会`
- `更适合你的沟通方式`

### 8.2 新模块定义

#### 模块 1：你的关系驱动力

解释你更偏向：

- 害怕失去连接
- 害怕失去边界
- 两边都不算特别强
- 两边都会被触发

#### 模块 2：你会在哪些时刻最容易被触发

按 ECR 维度解释常见触发场景：

- 回应变慢
- 情绪变淡
- 关系推进太快
- 被追问内心
- 冲突后没有修复

#### 模块 3：你靠什么重新稳定下来

不是讲“最佳匹配”，而是讲：

- 什么样的互动会让你重新有安全感
- 什么样的节奏会让你不那么想退

#### 模块 4：你在关系里的常见误会

重点讲误读机制：

- 你可能把忙理解成冷淡
- 你可能把靠近理解成压力
- 你明明在乎，但表达出来像后退

#### 模块 5：更适合你的沟通方式

给可执行建议，不要给鸡汤。

### 8.3 不建议再保留的老模块

建议下线或弱化：

- 最佳匹配
- 需磨合类型
- 哪种类型最配你

原因：

- 这更像旧式人格配对
- 不符合 ECR 核心解释方式
- 容易把连续维度讲成玄学配对

如果一定要保留“适合对象”，建议改为：

- **适合你的相处方式**
- **你更吃哪种回应风格**

而不是“你适合 INFJ / 你别碰某类型”这种表达。

## 九、小雅的话术怎么改

### 9.1 小雅目标

小雅不是复述结果卡片，而是做“翻译”。

她应该把 ECR 结果翻译成：

- 用户能代入的关系感受
- 用户常见的误会机制
- 用户下一步能怎么做

### 9.2 小雅语气目标

建议参考当前线上 MBTI 的成熟状态：

- 亲密
- 会说人话
- 有一点画面感
- 不端着
- 不羞辱
- 不过度搞笑

目标不是“毒舌判官”，而是“很会翻译关系的人”。

### 9.3 小雅话术结构建议

建议固定成 6 段：

1. 先说结论
2. 翻译两维结果
3. 描述关系里的典型状态
4. 说适合的回应方式
5. 说最容易吃亏的点
6. 给一到三句行动建议

### 9.4 小雅示例方向

#### 低回避 + 高焦虑

```text
你这次更偏高敏确认型。

简单说，你不是不敢靠近，反而是很想靠近。
只是关系一重要起来，你会特别在意对方有没有持续回应你。

所以你最容易累的，不是没人陪，而是那种忽冷忽热、话说一半、态度让你猜的关系。
你越在乎，越容易被这种不确定感牵着走。

你真正需要的，其实不是天天报备，
而是稳定、清楚、别让你反复猜。

你最容易吃亏的地方，是对方只是晚回一会儿，
你脑子里已经先把这段关系演崩了。

你接下来最该练的只有一件事：
别急着脑补，先把不安翻译成一句能说出口的话。
```

#### 高回避 + 低焦虑

```text
你这次更偏边界后撤型。

你不一定是不在乎，
只是关系一旦太密、太快、太需要你马上交出情绪，
你会本能地想往后退一点。

你不是对人冷，
你更像是对“失去自己的空间”很警觉。

所以你更适合那种能靠近你，
但不会步步紧逼的人。

你最容易吃亏的地方，是明明心里还有这段关系，
但动作上已经先撤了，
最后对方只会看到你的沉默，看不到你的在意。

你接下来最该练的，是在想退的时候先留一句话，
哪怕只是“我不是不想聊，我是想缓一下”。
```

### 9.5 小雅中不建议再用的旧表达

建议删除或少用：

- 赛博怨妇
- 装死大师
- 连体婴认证
- 洞穴伪人认证
- 反复横跳狂魔

可以保留少量轻微网感，但不要把用户钉死在嘲讽标签上。

## 十、是否保留“类型标签”

结论：

- **可以保留**
- **但必须降级为解释标签，不是测量实体**

### 10.1 可以保留的原因

- 用户需要一个记忆点
- 社交分享需要一句“我更偏哪一挂”
- 小雅开头也需要一个抓手

### 10.2 不能保留旧用法的原因

如果继续像现在这样：

- 出四组题
- 算四组分
- 选最高组

那就又回到旧逻辑了，不是 ECR。

### 10.3 推荐保留方式

保留“主标签”，但结果页明确以两维为主：

```text
你这次更偏「拉扯矛盾型」

关系不安度：72
亲密后撤度：74
```

这时用户知道：

- 标签是解释
- 分数才是底层结构

## 十一、前后端结构调整建议

### 11.1 题库数据结构

建议题目结构改成：

```python
{
  "index": 0,
  "text": "...",
  "options": [...],
  "dimension": "anxiety",  # or "avoidance"
  "reverse": False,
}
```

不再出现：

- `secure`
- `fearful`

作为题目维度。

### 11.2 结果数据结构

建议结果结构改成：

```json
{
  "type_code": "anxious_low_avoidance",
  "scores": {
    "anxiety": 78,
    "avoidance": 29
  },
  "dimension_rows": [
    {
      "key": "anxiety",
      "name": "关系不安度",
      "score": 78,
      "level": "high",
      "trait": "回应敏感"
    },
    {
      "key": "avoidance",
      "name": "亲密后撤度",
      "score": 29,
      "level": "low",
      "trait": "靠近自如"
    }
  ],
  "labels": ["高敏确认型", "回应敏感", "靠近自如"],
  "interpretation_data": { ... }
}
```

### 11.3 interpretation_data 结构建议

```json
{
  "summary": "...",
  "relationship_drive": "...",
  "triggers": "...",
  "stabilizers": "...",
  "common_misread": "...",
  "communication_advice": "...",
  "disclaimer": "..."
}
```

### 11.4 匹配逻辑建议

现有 `calculate_love_match` 也应同步改。

建议不要再做：

- 安全型 + 任何 = 高分
- 焦虑 + 回避 = 扣分

建议改成：

- 双方 `anxiety` / `avoidance` 的距离分析
- 双方触发机制是否容易互相撞上
- 双方修复方式是否兼容

第一阶段如果不改匹配，也至少要：

- 暂时下线依恋匹配度强结论
- 或标注“轻参考”

## 十二、和 MBTI 风格怎么对齐

### 12.1 应继承的东西

从 MBTI 当前较成熟风格里继承：

- 主标题短
- 一句话能记住
- 有画面感但不过火
- 先说“你会怎么感受”，再说“你是什么”
- 小雅像翻译，不像裁判

### 12.2 不要继承的东西

不要继承 MBTI 历史稿里的：

- 过强配对结论
- 绝配 / 虐心 / 最佳对象标签
- 为了好玩牺牲可信度的夸张表达

### 12.3 推荐语气样式

推荐语气是：

- “你不是怎样怎样，你更像是……”
- “你真正怕的不是……而是……”
- “你并不是不在乎，只是……”

这是很适合依恋主题的表达方式。

## 十五、结论

这次重构最重要的不是“把现在的四个名字换成新名字”，而是：

- **把底层从四型独立测验改成 ECR 两维测量**
