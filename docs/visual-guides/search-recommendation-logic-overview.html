搜索推荐内部逻辑梳理

这份页面讲的是：系统到底怎么从一堆资料里，筛出候选人、怎么算分、怎么做双向匹配、最后为什么会给出 strict、compatible、fallback 三层结果。

主入口：execute_search_request 主评分：evaluate_candidate 双向偏好：evaluate_reciprocal_compatibility 输出分层：strict / compatible / fallback

一句话先讲明白

现在这套推荐，不再是“只要没卡进条件就直接删掉”，而是：

1

先做必要硬筛选

比如性别不符、资料状态不符、必须不能抽烟但对方抽烟、年龄差太大、身高差太大这种，先挡掉。

2

再做接近度打分

年龄、身高、学历、收入、城市这些不是只看“中没中”，而是看“离理想值有多近”。

3

再叠加双向匹配

不只是“你觉得对方行不行”，还会看“对方的择偶要求，你自己能不能比较接近”。

4

最后分层展示

strict 是很标准的，compatible 是接近但带风险提示，fallback 是没结果时兜底的兼容对象。

整体链路

真实执行顺序：

build_search_request → normalize_request_criteria → build_self_profile → 逐批加载资料 → evaluate_candidate → 排序与多样性裁剪 → strict / compatible 分层 → 没结果时生成 fallback

大白话： 系统先把“你想找什么样的人”和“你自己是谁”整理好，再一条条看资料。每看一条，就会判断：

  • 这个人先别说合不合适，最基本能不能入场？
  • 能入场的话，离你的理想像不像？
  • 你觉得她不错的同时，她的择偶要求你自己够不够接近？
  • 最后总分高不高，风险多不多。

结果层级

层级 什么意思
strict 主要条件都卡得比较准，风险也不重。
compatible 有些地方不是满命中，但很接近，值得看。
fallback 前两层都没有时，给你一些还能聊的兜底对象。
strict = 更稳 compatible = 有偏差但能聊 fallback = 兜底看缘分

第一层：先筛什么

这里不是所有条件都硬筛。现在系统只会把一部分真的很硬的条件先挡掉。

条件类型 现在大致怎么处理 大白话解释
性别 / 资料状态 / 最低认证 通常直接筛 这些不是“差一点也行”，而是基础门票。
必须项 must_have 没提到就淘汰 用户都说“必须有了”，那就不该再放宽。
明确反感项 must_not_have 命中就淘汰或降权 比如你明确说不能抽烟，对方资料里写抽烟，那就没必要往下算。
年龄 / 身高 太远才淘汰，接近就保留 不是出了区间就死，而是差太多才死。
城市 当前城市不符时，看定居城市能不能救 现在不再是“现居不对就没了”，如果对方目标定居城市对，也能留下。

第二层：主匹配怎么打分

主匹配就是“站在搜索发起人角度”，看候选人离你的理想有多近。

  • 年龄：在区间里分最高，差 1 岁比差 3 岁更高。
  • 身高：在区间里更高，差 2cm 比差 5cm 更高。
  • 学历：本科对硕士，比大专对硕士更接近，所以更高。
  • 收入：在理想区间高分，略低于下限还能保留，明显低很多才重扣；高于上限通常不算明显负向。
  • 城市：当前同城最高，当前异地但定居同城次之。
  • 偏好词：命中 prefer 会加分，但不是生死线。
大白话： 现在系统像在给每个人打“像不像你理想对象”的分，不像以前那种 Excel 过滤器。

第三层：双向匹配怎么做

双向匹配就是“你看得上她”的同时，也要看“她的择偶要求，你自己是不是比较接近”。

  • 对方要求年龄 28-32，你 27 岁，会给兼容分。
  • 你 25 岁，也许还保留，但 bonus 更低。
  • 对方要求收入 30-50 万，你 60-70 万，不再一刀杀掉。
  • 对方要求学历博士，你是硕士，会比本科拿更高 reciprocal bonus。
大白话： 双向不是只看“过没过”，而是看“你有多像她想找的人”。

第四层：风险提示怎么来的

很多人不是被直接淘汰，而是会带着风险提示进入 compatible。

典型风险标记 背后意思 实际效果
年龄略偏离理想区间，但仍然接近 差一点点，不至于直接淘汰 保留，降一点风险分
当前城市未命中，但定居城市命中 现在不在这，但未来目标城市对 保留，但通常不会排在同城前面
收入高于预期上限，但通常不构成负向问题 超了上限，但不是坏事 保留，仍有分数
对方年龄要求接近命中，可作为兼容匹配 双向上也接近 进入 reciprocal bonus

一个完整例子

搜索人 A：

  • 想找：女，27-30 岁，身高 165-170，城市无锡，学历最低硕士，理想收入 30-50 万
  • 自己：28 岁，无锡，本科，40 万
候选人 资料 系统怎么想 大概率层级
A1 29 岁，168cm，无锡，硕士，35-45 万 年龄命中、身高命中、城市命中、学历命中、收入命中，双向也很顺 strict
A2 31 岁，172cm，上海但定居无锡，本科，28-32 万 年龄差 1 岁，身高高 2cm，当前不在无锡但定居目标对，学历低一档，收入接近 compatible
A3 25 岁，160cm，杭州，大专，8-12 万 年龄差远、身高差远、城市不对、学历差距大、收入差距大 大概率直接淘汰或只在 fallback
A4 28 岁，167cm，无锡，硕士，60-70 万 除了收入高于预期上限，其他都很好；系统不会因为“高于 50 万”把她踢掉 strict 或高分 compatible

为什么以前会“搜不到人”

  • 以前更像硬筛选：不在区间里就没了。
  • 比如收入 100 万，但对方写 30-50 万，旧逻辑可能直接过滤。
  • 结果就是：明明有能聊的人，页面却显示没有匹配对象。
现在的改法： 把很多“并不是真正不能接受”的条件，改成“接近度打分 + 风险提示”。

现在这套系统最像什么

最像一个“带风险解释的推荐排序器”，而不是一个纯过滤器。

  • 过滤器思路：不符合就删。
  • 推荐器思路：越接近越靠前，不完美也可以保留。
  • 解释层思路：告诉你为什么靠前、哪里有偏差、下一步该确认什么。

当前版本已经做到什么

年龄：渐进打分 身高：渐进打分 学历：接近度分层 收入：理想带分层 城市：同城 / 定居同城分层 reciprocal：接近度 bonus
如果后面还要继续精修，最自然的方向是：把城市关系做得更细，比如同城、邻城通勤、短途异地、长期异地四层，而不是只靠城市名字相等。
