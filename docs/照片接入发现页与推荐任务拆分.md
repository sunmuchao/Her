# 照片接入发现页与推荐任务拆分

## 1. 先说任务拆分原则

这次任务拆分不是从零设计，因为仓库里已经有一部分照片匹配能力落地了。

所以原则要改成：

1. 不重做已经落地的排序接入
2. 先补“生产层”，再补“闭环层”
3. 每一期都尽量可独立上线
4. 继续保持发现页和推荐系统共用一套底层能力

一句大白话：

**不是从地基开始盖，而是先把已经有的楼层接着往上封顶。**


## 2. 先明确哪些已经算完成

这些不要再当成待设计项：

1. 照片相关表结构已经存在
2. 照片特征访问层已经存在
3. `partner_search` 已经能读取照片偏好并叠加照片 bonus
4. 发现页和推荐系统已经把 `requester_id + persona_source` 往下传
5. 发现页 `express_interest` 已经有最小正反馈回流

对应代码：

- `db_migrations/targets/persona/m0014_add_photo_matching_tables.py`
- `profile_service/api.py`
- `match_domain/appearance_features.py`
- `partner_search/search_runtime_helpers.py`
- `partner_search/search_matching.py`
- `external-systems/partner-discovery-system/discovery_system/service.py`


## 3. 任务分期

建议拆成 5 期：

1. P0：现状对齐与缺口确认
2. P1：照片特征生产层
3. P2：行为回流补全
4. P3：偏好历史聚合重建
5. P4：照片语义向量与 Agent 理解层


## 4. P0：现状对齐与缺口确认

### Task P0-1：确认当前照片主数据来源

内容：

- 确认候选人照片、头像、照片列表当前从哪里取
- 确认搜索链路现在能拿到哪些基础照片字段
- 确认前端卡片展示实际依赖哪些字段

交付物：

- 一份照片数据来源说明
- 一份搜索链路可用照片字段清单

验收标准：

- 能明确回答“照片原始数据从哪来，搜索时当前能拿到什么”

### Task P0-2：确认 `profile_photo_features` 当前真实使用字段

内容：

- 对齐 migration、访问层、排序层实际用到哪些字段
- 删掉文档里想当然但代码没用到的字段
- 标记哪些字段是一期必需，哪些是后续可扩展

交付物：

- 一份当前字段使用矩阵

验收标准：

- 能明确回答“哪些字段已经被排序消费，哪些还只是预留”

### Task P0-3：确认缺失触发点

内容：

- 找到照片上传、替换、删除的后端入口
- 确认哪些入口适合挂异步分析任务
- 确认失败重试和重算时机

交付物：

- 一份照片分析触发点说明

验收标准：

- 能明确回答“照片更新后从哪里触发分析最顺”


## 5. P1：照片特征生产层

这一期是最关键的一期。

### Task P1-1：接照片分析异步任务入口

内容：

- 在上传、替换、删除照片后触发异步任务
- 不阻塞主流程
- 支持失败重试

交付物：

- 照片分析任务入口
- 状态流转定义

验收标准：

- 照片变化后能进入 `pending -> processing -> done/failed`

### Task P1-2：实现主图选择

内容：

- 多张图时选择最适合做主分析的一张
- 优先单人、清晰、非模糊、正脸

交付物：

- 主图选择逻辑

验收标准：

- 同一组照片重复跑，主图选择稳定

### Task P1-3：产出基础照片分

内容：

- 产出 `appearance_score_global`
- 产出 `photo_quality_score`
- 产出 `photo_authenticity_score`

交付物：

- 照片基础评分任务
- 写入 `profile_photo_features`

验收标准：

- 给定照片样本，库里能稳定看到基础分

### Task P1-4：产出长相风格维度

内容：

- 先做少量稳定维度：
- `mature_score`
- `clean_score`
- `gentle_score`
- `sunny_score`
- `stylish_score`

交付物：

- 风格维度评分逻辑

验收标准：

- 同类照片能产出同一套结构化维度

### Task P1-5：产出口语化长相描述

内容：

- 生成 `appearance_summary`
- 生成 `appearance_tags_json`
- 描述要自然，但不能冒犯

交付物：

- 长相描述生成逻辑

验收标准：

- 任意候选人都能产出可读、可复用、可向量化的描述


## 6. P2：行为回流补全

现在只有最小正反馈，这一期要把行为信号做完整。

### Task P2-1：补发现页负反馈事件

内容：

- 接入 `skip`
- 接入 `quick_pass`
- 接入 `explicit_dislike`

交付物：

- 负反馈事件写入逻辑

验收标准：

- 用户跳过和明确不喜欢会被记录到 `appearance_feedback_events`

### Task P2-2：补弱正向行为事件

内容：

- 接入 `detail_view`
- 接入停留时长
- 接入收藏或进一步了解

交付物：

- 弱正向行为记录逻辑

验收标准：

- 系统能区分“看了但没兴趣”和“看得比较认真”

### Task P2-3：补聊天侧强正向信号

内容：

- 接入 `chat_started`
- 接入 `chat_replied`
- 接入 `chat_continued`

交付物：

- 聊天行为回流逻辑

验收标准：

- 系统能区分“一时点了喜欢”和“真正进入互动”

### Task P2-4：定义事件权重

内容：

- 给不同事件定义正负权重
- 区分强正样本、弱正样本、弱负样本、强负样本

交付物：

- 一份事件权重表

验收标准：

- 排名系统和偏好重建都能复用同一套权重定义


## 7. P3：偏好历史聚合重建

这一期解决“现在偏好更新太轻、太即时”的问题。

### Task P3-1：实现历史事件聚合器

内容：

- 批量读取 `appearance_feedback_events`
- 按时间窗和事件权重聚合
- 生成用户审美偏好中心

交付物：

- 偏好聚合任务

验收标准：

- 同一用户多次行为能汇总成稳定偏好结果

### Task P3-2：重建 `user_appearance_preferences`

内容：

- 根据历史行为重算偏好维度
- 更新样本数、更新时间和可信度

交付物：

- 偏好重建逻辑

验收标准：

- `user_appearance_preferences` 不再只像“最后一次喜欢了谁”

### Task P3-3：让照片 bonus 使用聚合后偏好

内容：

- 搜索排序继续复用当前 bonus 入口
- 但 bonus 输入改成历史聚合后的偏好结果

交付物：

- 偏好 bonus 输入源切换

验收标准：

- 同一用户偏好多次搜索结果更稳定，不会因为一次操作大幅漂移

### Task P3-4：冷启动和低样本保护

内容：

- 新用户没有样本时只吃基础照片分
- 样本少时降低个体偏好权重
- 样本多时再逐步提高

交付物：

- 偏好置信度策略

验收标准：

- 新用户不会因为噪声数据被带偏


## 8. P4：照片语义向量与 Agent 理解层

这一期解决“用户说人话，系统也能懂照片偏好”的问题。

### Task P4-1：新增照片向量类型

内容：

- 增加 `appearance_profile`
- 增加 `appearance_preference`

交付物：

- 向量类型定义
- 写入链路接入

验收标准：

- 照片描述和偏好聚合结果都能写入现有向量体系

### Task P4-2：把照片语义接进 `vector_filter`

内容：

- 支持照片语义 include/exclude
- 支持“成熟一点”“清爽一点”“不要太幼态”这类条件

交付物：

- `vector_filter` 照片语义扩展

验收标准：

- 自然语言照片偏好能进入真实筛选链路

### Task P4-3：Agent 翻译用户照片偏好

内容：

- 把用户口语化需求翻译成系统条件
- 优先落成结构化维度和向量条件

交付物：

- 偏好理解提示词或解释层逻辑

验收标准：

- 用户说“想找成熟一点的”，系统能落到可执行条件

### Task P4-4：Agent 生成推荐解释文案

内容：

- 基于已有照片特征做解释
- 不允许 agent 脱离底层特征自由发挥

交付物：

- 推荐解释生成逻辑

验收标准：

- 推荐文案和底层照片特征口径一致


## 9. 建议优先级

如果只能先做一部分，建议顺序是：

1. 先做 P1，补照片特征生产层
2. 再做 P2，补正负反馈事件
3. 再做 P3，补历史聚合重建
4. 最后做 P4，补语义向量和 Agent 理解层

原因很简单：

- 没有生产层，排序吃不到稳定数据
- 没有反馈层，动态偏好就是空的
- 没有历史聚合，偏好会飘
- 语义层和 Agent 层是增强，不是地基


## 10. 一句话总结

当前任务重点已经不是“把照片接进发现页和推荐”，因为这一步已经部分完成了。

现在真正该拆解和推进的是：

**照片特征生产、用户行为回流、历史偏好重建、照片语义向量化。**
