🔍 Discovery System 所有 Tool 完整查询链路（含实战示例）

📖 核心说明

这份文档梳理了所有7个 Tool 的完整查询链路，每个 Tool 都附带实战示例：
从用户对话 → AI 调用 Tool → 逐层穿透 → 数据库查询 → 返回数据 → 前端渲染。

设计理念：Agent Native（AI 主导决策）+ 三层分离架构（Tool 层 → Service 层 → Data 层）+ 单一真相来源（规则只在 Prompt 中表达）。

sync_requester_persona_memory（同步用户偏好）
职责：将用户明确表达的择偶偏好同步到长期记忆（Persona Memory）
💡 实战示例：用户说"我喜欢苏州的女生，年龄26-30岁"
👤 用户："我喜欢苏州的女生，年龄26-30岁"
⬇️
1️⃣ AI 理解意图 + 调用 Tool
AI 思考：用户表达了明确的择偶偏好，应该同步到长期记忆，后续推荐更精准
AI 构建：patch_json='{"preferred_cities":["苏州"], "preferred_age_range":[26,30]}'
AI 调用：sync_requester_persona_memory(patch_json='{"preferred_cities":["苏州"], "preferred_age_range":[26,30]}')
⬇️
2️⃣ Tool 层执行（agent_runtime.py）
参数解析：
patch_json → {"preferred_cities":["苏州"], "preferred_age_range":[26,30]}

硬约束校验：
- 必须是 dict 类型 ✓

调用下一层：
run_input.sync_requester_persona_memory({"preferred_cities":["苏州"], "preferred_age_range":[26,30]})
⬇️
3️⃣ Service Integrations 层（service_integrations.py）
拆分 patch：
split_persona_patch → {"profile_part": {}, "persona_part": {"preferred_cities":["苏州"], "preferred_age_range":[26,30]}, "search_part": {"target_cities":["苏州"], "target_age_min":26, "target_age_max":30}}

更新搜索条件：
session.state["working_criteria"] = {"target_cities":["苏州"], "target_age_min":26, "target_age_max":30}

调用 Persona 同步：
upsert_persona_memory({"source": "...", "user_key": "12345", "patch": {"preferred_cities":["苏州"], ...}})
⬇️
4️⃣ Persona Memory Engine 层
加载现有 Persona：
fetch_persona → {"user_key": "12345", "target_cities": [], ...}

合并 patch：
_merge_persona_patch → {"user_key": "12345", "target_cities": ["苏州"], "target_age_min": 26, "target_age_max": 30}

生成 observation：
{"field_name": "preferred_cities", "field_value": "苏州", "source_type": "explicit", "evidence_text": "我喜欢苏州的女生"}
⬇️
5️⃣ MySQL 数据库写入
写入 Persona：
INSERT INTO user_personas (user_key, target_cities, target_age_min, target_age_max, ...) VALUES ('12345', '苏州', 26, 30, ...) ON DUPLICATE KEY UPDATE ...

写入 Observation：
INSERT INTO user_persona_observations (user_key, field_name, field_value, source_type, evidence_text) VALUES ('12345', 'preferred_cities', '苏州', 'explicit', '我喜欢苏州的女生')
⬇️
6️⃣ 返回结果
Tool 层返回：
{"synced": true, "user_key": "12345", "patch_keys": ["preferred_cities", "preferred_age_range"]}
⬇️
🤖 AI："好的，我记下了，你偏好苏州26-30岁的女生。以后推荐会更精准。
[继续对话]"

🎯 核心总结
这份文档梳理了所有7个 Tool 的完整查询链路 + 实战示例：

1️⃣ search_partner_candidates：用户说"推荐苏州26-30岁女生" → Tool → Service → MySQL → 返回候选人 → AI 展示
2️⃣ sync_requester_persona_memory：用户说"我喜欢苏州的女生" → Tool → Persona Engine → MySQL user_personas → 返回 synced
3️⃣ propose_requester_profile_update：用户说"我28岁了" → Tool → Profile Updates → MySQL profile_update_requests → 返回提议卡片
4️⃣ create_saved_search_subscription：用户点击"持续留意" → Tool → Recommendation System → MySQL subscriptions → 返回订阅
5️⃣ reply_to_user：用户问"为什么推荐第一位" → Tool → Decision Models → Service → 前端渲染消息
6️⃣ show_candidates：AI 搜索后 → Tool → Service → View Models → 前端渲染候选人卡片
7️⃣ suggest_assessment：用户问"我适合什么性格的人" → Tool → Personality Reader → MySQL user_personas → 返回测评引导/性格信息

设计理念：Agent Native（AI 主导决策）+ 三层分离（Tool 层 → Service 层 → Data 层）+ 单一真相来源（规则只在 Prompt）
