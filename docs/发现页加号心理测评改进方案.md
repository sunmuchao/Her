# 发现页加号心理测评改进方案

> 整理日期：2026-06-05
> 适用范围：发现页加号菜单中的全部心理测评入口
> 当前测评范围：`MBTI`、`依恋风格`、`大五人格`、`爱情三元论`、`价值观拍卖`
> 相关实现：`frontend/her-app/components/her/discover-page.tsx`、`frontend/her-app/components/assessment/assessment-themes.ts`、`assessment/*`

## 1. 改造目标

把“发现页加号里的心理测评”从“5个功能按钮”升级成“可理解、可选择、可持续利用的测评中心”。

本次改造核心解决 4 件事：

1. 用户现在看不懂各测评区别，不知道该选哪个。
2. 入口信息太少，用户不知道为什么值得做。
3. 前后端名称、题量、时长不统一，影响专业感。
4. 做完后的结果价值没有被充分放大，用户感知不到对推荐和聊天的帮助。

## 2. 当前问题

### 2.1 入口层信息不足

当前发现页加号中的心理测评入口主要是图标加名称，缺少以下关键信息：

- 适合谁做
- 预计时长
- 题量
- 做完会得到什么
- 结果会如何被系统使用

这会导致用户在点击前无法完成判断，只能靠猜。

### 2.2 命名不统一

同一个测评当前存在多套名称：

- 发现页按钮：`相处模式`
- 前端主题：`依恋风格测试`
- 后端介绍卡：`相处模式测验`

这会让用户感觉产品定义不稳定，也不利于前后端统一维护。

### 2.3 时长与题量不统一

当前至少存在一处明确不一致：

- 前端主题配置：`4分钟`、`16题`
- 后端真实题库与介绍卡：`3分钟 · 12题`

如果用户点进去发现和入口描述不一样，会直接损伤信任感。

### 2.4 测评优先级没有体现产品策略

当前 5 个测评入口是并列平铺的，看起来重要性一致。但从产品价值上看，它们并不等价：

- `依恋风格` 更适合做首测，和亲密关系行为最直接相关
- `价值观拍卖` 最轻、最快、差异化最强
- `大五人格` 更适合提供稳定的人格画像
- `MBTI` 更偏趣味和传播
- `爱情三元论` 更适合做关系补充分析

如果继续同权重展示，会弱化真正值得优先推荐的测评。

### 2.5 结果价值表达不够

当前测评体系本身的产品理念是“测评不是一次性测试，而是持续画像”，但用户未必能明确感知到：

- 结果会不会影响推荐对象
- 结果会不会影响小雅的聊天方式
- 结果会不会写入自己的画像标签
- 结果能不能帮自己更好理解关系问题

如果这些价值不明确，测评就容易被当成一次性娱乐内容。

### 2.6 部分测评偏长

以加号入口的使用场景来看，用户往往是临时点开、希望快速得到收获。当前存在两类偏长测评：

- `MBTI`：48题
- `大五人格`：50题

如果没有更好的预期管理和分段设计，完成率容易受影响。

## 3. 总体改造方向

建议把现有测评系统拆成三个连续层次来做优化：

1. 入口层：解决“我该选哪个”
2. 过程层：解决“我做得下去”
3. 结果层：解决“我做完有什么实际帮助”

同时增加第四层：

4. 回流层：解决“测评结果如何持续影响推荐、标签和小雅对话”

## 4. 完整改造方案

### 4.1 入口层改造

把现在的“图标 + 名称”按钮，升级成“测评信息卡片”。

每张卡片建议包含：

- 测评名称
- 一句话用途
- 时长
- 题量
- 适合谁
- 做完的收益
- 当前状态

建议展示结构：

- 标题：`依恋风格`
- 副标题：`看你在关系里为什么容易焦虑、回避，或者能稳定给出安全感`
- 元信息：`3分钟 · 12题`
- 收益说明：`结果可用于优化聊天建议和关系判断`
- 状态标签：
  - `推荐先做`
  - `已完成`
  - `继续上次进度`

这样用户进入菜单时，不需要理解心理学术语，也可以快速判断该做哪个。

### 4.2 入口排序与分组重构

建议默认顺序调整为：

1. `依恋风格`
2. `价值观拍卖`
3. `大五人格`
4. `MBTI 恋爱测试`
5. `爱情三元论`

更推荐的展示方式是直接分组：

#### 推荐先做

- `依恋风格`
- `价值观拍卖`
- `大五人格`

#### 延伸探索

- `MBTI 恋爱测试`
- `爱情三元论`

这样的好处是用户不需要猜“平台推荐我先做什么”，系统会直接表达产品策略。

### 4.3 命名统一方案

建议统一成以下名称：

- `MBTI 恋爱测试`
- `依恋风格`
- `大五人格`
- `爱情三元论`
- `价值观拍卖`

不再混用：

- `相处模式`
- `相处模式测验`
- `依恋风格测试`

统一原则：

- 面向用户的名称只保留一套
- 前端入口、测评主题、后端介绍卡、结果页、文档使用同一名称
- 如果需要技术字段区分，保留 `assessment_type` 即可，不把技术名暴露给用户

### 4.4 时长与题量统一方案

需要建立“单一真相源”，统一输出以下信息：

- 标题
- 副标题
- 时长
- 题量
- 奖励文案
- 推荐优先级

所有入口、介绍卡、结果页、文档都应从同一份配置读取，不允许前端、后端分别维护两套口径。

短期优先修复项：

1. 修复 `依恋风格` 的时长与题量不一致问题
2. 逐个核查 `MBTI`、`大五人格`、`爱情三元论`、`价值观拍卖` 的入口描述与后端真实内容
3. 建立统一配置表供前后端与文档同步引用

### 4.5 每个测评的产品定位重写

#### MBTI 恋爱测试

定位：

- 趣味性强
- 传播性强
- 适合社交分享

当前问题：

- 题量偏长
- 完整类型配置还需要补齐

建议：

- 保留完整版
- 增加“极速版初判”
- 结果页突出“恋爱中的你像什么人”
- 补齐全部 16 型完整内容

推荐文案：

`想快速知道你谈恋爱像哪种人，先做这个。`

#### 依恋风格

定位：

- 最强关系解释力
- 最适合首测

当前问题：

- 命名混乱
- 口径不一致

建议：

- 作为默认推荐项
- 结果聚焦“触发点”和“关系里的典型反应”
- 输出场景化内容：
  - 对方回消息慢时
  - 对方突然靠近时
  - 发生冲突时
  - 关系推进时

推荐文案：

`如果你总在关系里容易没安全感，先做这个。`

#### 大五人格

定位：

- 最稳健的人格画像
- 更科学、更连续

当前问题：

- 学术感较强
- 用户不一定能立刻理解收益

建议：

- 把“五维得分”翻译成“你在相亲和长期关系中的行为方式”
- 突出“比 MBTI 更细、更稳定”
- 增加长期相处建议

推荐文案：

`如果你想要更准确、不是只看类型标签，做这个。`

#### 爱情三元论

定位：

- 关系结构测评
- 适合作为补充分析

当前问题：

- 做完后行动价值不够明确

建议：

- 结果聚焦“你当前更缺亲密、激情还是承诺”
- 增加与小雅后续对话联动的问题引导

推荐文案：

`适合想看自己更重亲密、激情还是承诺的人。`

#### 价值观拍卖

定位：

- 最有特色
- 最轻松
- 最适合拉高点击率

当前问题：

- 差异化没有被充分放大

建议：

- 作为新人首推项之一
- 明确打上 `最快开始`
- 结果直接映射到择偶偏好
- 明示会影响推荐对象的侧重点

推荐文案：

`最快看出你找对象最看重什么，第一次做推荐先选它。`

### 4.6 测评开始前引导优化

在 intro 卡中增加三个固定信息块：

1. 你会得到什么
2. 需要多久
3. 做完结果会怎么被使用

建议示例：

`这不是一次性测试。做完后：`

1. `小雅会更懂你在关系里的状态`
2. `推荐对象会更贴近你的偏好`
3. `你会看到自己的关系优势和常见卡点`

这样可以提升开始率和用户预期管理能力。

### 4.7 测评过程优化

为了降低中途流失，建议加入以下机制：

1. 开始前明确显示总题数和预计时长
2. 长测评增加阶段反馈
3. 长测评支持分段完成
4. 断点续做状态前置展示
5. 保持对话感，避免太像考试

具体建议：

- `MBTI` 可按 4 个维度拆段
- `大五人格` 可按 5 个维度拆段
- 每一段结束都给一句阶段反馈
- 对未完成测评，在入口卡片上显示：
  - `上次做到第 8/12 题，继续吗？`

### 4.8 结果页优化

每个测评结果页建议固定输出 4 块内容：

1. `你是什么`
2. `你在关系里通常怎么表现`
3. `你最容易卡在哪`
4. `你下一步可以怎么做`

示例：

- `你是什么`：焦虑型依恋 / ENFP / 高宜人性
- `你在关系里通常怎么表现`：习惯高频确认、需要回应、对关系变化敏感
- `你最容易卡在哪`：过度脑补、需求不敢说、对冷淡反应过强
- `你下一步可以怎么做`：先表达感受，再表达期待，先确认事实，不先脑补结论

重点不是只给标签，而是给解释和行动建议。

### 4.9 结果回流到主流程

这是本次方案里最关键的一层。

这次不再把“测评回流”理解成“给用户贴更多标签”，而是拆成三层数据：

1. 过程审计层
2. 完整结果层
3. 画像摘要层

这样做的原因很直接：

- AI 匹配真正需要的是稳定、结构化、可推理的事实，不是趣味标签
- 完整结果要能追溯、重解读、重放，但不应该全部塞进主画像
- 展示文案、小雅解读、运营包装语可以保留，但不应该污染匹配主字段

#### 4.9.1 数据分层方案

##### A. 过程审计层

继续使用 `user_persona_observations` 记录测评过程数据：

- `assessment.session`
- `assessment.answer.{n}`
- `assessment.result`
- `assessment.interpretation`
- `assessment.xiaoya_message`

这一层的目标是：

- 保留完整答题过程
- 支持断点续传
- 支持审计和排查
- 支持后续重新生成解读

这一层不是 AI 匹配主读模型。

##### B. 完整结果层

新增 `assessment_results` 表，按“一次完成的测评结果一条记录”存储完整快照。

建议字段：

```sql
CREATE TABLE assessment_results (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_key VARCHAR(64) NOT NULL,
  assessment_id VARCHAR(64) NOT NULL,
  assessment_type VARCHAR(32) NOT NULL,
  result_version VARCHAR(32) NOT NULL DEFAULT 'v1',
  summary_json JSON NULL,
  raw_result_json JSON NOT NULL,
  interpretation_json JSON NULL,
  source_channel VARCHAR(32) NOT NULL DEFAULT 'assessment',
  completed_at DATETIME NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_assessment_id (assessment_id),
  KEY idx_user_type_time (user_key, assessment_type, completed_at DESC)
);
```

这一层保存：

- 完整分数
- 完整结果对象
- 完整解读对象
- 结果版本

这一层不要求轻量，重点是可追溯。

##### C. 画像摘要层

`user_personas.self_personality_traits_json` 继续保留，但收敛成“AI 匹配主画像摘要”。

这里的原则是：

- 只存关键结构化事实
- 不存展示标签
- 不存长文案
- 不存完整过程
- 不额外建 `user_persona_trait_tags` 标签表

原因是：

- `labels` 对 AI 匹配没有稳定帮助，模型会自己理解 `ENFP`、`secure attachment`、高开放性等结构化结果
- 单独维护 trait tag 表会造成口径漂移、重复存储和同步成本

#### 4.9.2 每个测评写入主画像时保留什么

##### MBTI

保留：

- `assessment_id`
- `type_code`
- 四维分数
- `completed_at`

不保留到主画像：

- `labels`
- 恋爱说明书全文
- 小雅消息
- 题目过程

##### 相处模式 / 依恋风格

保留：

- `assessment_id`
- `type_code`
- `anxiety`
- `avoidance`
- `completed_at`

不保留：

- 长解释文案
- 结果页装饰性标签

##### 大五人格

保留：

- `assessment_id`
- 五维分数
- `completed_at`

不保留：

- 趣味标签
- 长段解释文案

##### 爱情三元论

保留：

- `assessment_id`
- `type_code`
- 三维分数
- `completed_at`

##### 价值观拍卖

保留：

- `assessment_id`
- `value_type`
- `top_values`
- `tensions`
- `completed_at`

不保留到主画像：

- 全量 `bids`
- 全量隐藏价值对象
- AI 解读全文

#### 4.9.3 写入流程约束

每个测评完成后，统一按 3 步执行：

1. 写 `user_persona_observations`
2. 写 `assessment_results`
3. merge 写 `user_personas.self_personality_traits_json`

这里的关键约束是：

- 主画像必须是局部 merge，不能整字段覆盖
- `self_personality_traits_json` 只更新对应测评节点
- `MBTI`、`依恋`、`大五`、`三元论`、`价值观拍卖` 必须可以长期共存

这意味着当前“直接整段覆盖 `self_personality_traits_json`”的实现方式需要废弃。

#### 4.9.4 回流到业务主流程

在这个数据结构下，测评结果继续回流到 3 个业务环节：

##### 推荐解释

在推荐对象或推荐理由中加入更具体的话术，例如：

- `你偏好稳定型互动，这位更适合慢热相处`
- `你更重视价值观一致，这位在家庭观和生活节奏上更接近你`

##### 小雅对话策略

不同结果影响小雅说话方式：

- 焦虑型：更强调安抚与结构化建议
- 回避型：减少压迫式追问
- 高情绪敏感：更注意措辞缓冲

##### 后续补测引导

系统可以根据已完成情况继续推荐补测：

- 已做 MBTI 但未做价值观拍卖，提示补齐长期关系判断信息
- 已做价值观拍卖但未做依恋风格，提示补齐亲密关系行为模式

#### 4.9.5 用户可见标签的定位

结果页和主页仍然可以展示趣味标签、类型昵称、总结文案。

但这些内容的定位应明确为：

- 展示层文案
- 用户自选的主页表达素材
- 对话中的辅助解释

而不是：

- AI 匹配主字段
- 独立结构化标签表
- 必须长期持久化到 `self_personality_traits_json` 的核心数据

### 4.10 结果分享与传播

对 `MBTI` 和 `价值观拍卖` 这类更适合分享的测评，建议增加轻量传播能力：

- 一句可复制的“我的恋爱说明”
- 一张可展示的结果摘要卡
- 一段可用于聊天或主页展示的结论文案

重点不一定是外部社交平台，而是提升产品内回访和讨论意愿。

## 5. 数据与实验方案

改版后建议重点观察以下指标：

1. 入口曝光后的点击率
2. 各测评开始率
3. 各测评完成率
4. 测评完成后继续与小雅聊天的比例
5. 测评结果用于推荐解释的覆盖率
6. 测评用户与未测评用户的推荐互动率对比
7. 不同测评对留存的贡献差异

建议先做 A/B 测试：

- A 版：现有简版入口
- B 版：卡片化入口 + 时长 + 用途 + 推荐标签

优先比较：

- 点击率
- 开始率
- 完成率

## 6. UI 改版建议

建议将当前折叠菜单改为“标题 + 副标题 + 竖向卡片列表”。

推荐结构：

- 标题：`心理测评`
- 副标题：`了解自己，也让小雅更懂你`

每张卡片显示：

- 图标
- 标题
- 副标题
- 时长与题量
- 状态标签
- 操作按钮

按钮文案建议：

- 未做：`开始`
- 未完成：`继续`
- 已完成：`查看结果`

这样用户不只是“看到功能”，而是“看到自己下一步该做什么”。

## 7. 落地实施顺序

### 第一阶段：口径修复

目标：先清掉“不严谨”的问题

任务：

1. 统一所有名称
2. 统一时长与题量
3. 建立单一配置源
4. 对齐前端、后端、结果页与文档

### 第二阶段：入口重做

目标：提升点击率与开始率

任务：

1. 图标按钮改为信息卡片
2. 增加推荐标签
3. 重排顺序并分组
4. 增加“继续上次进度”状态

### 第三阶段：结果增强

目标：提升完成后的感知价值

任务：

1. 增加“关系表现”解释
2. 增加“常见卡点”
3. 增加“下一步建议”
4. 明示结果已用于推荐和聊天

### 第四阶段：回流链路完善

目标：让测评真正服务主流程

任务：

1. 标签确认
2. 推荐解释增强
3. 小雅对话个性化
4. 补测推荐策略

## 8. 推荐文案草案

### 依恋风格

看你在关系里为什么容易焦虑、回避，或者能稳定给出安全感  
`3分钟 · 12题`

### 价值观拍卖

用最轻松的方式看出你找对象最看重什么  
`2-3分钟 · 轻互动`

### 大五人格

比类型标签更细，帮你看清长期相处中的真实风格  
`8-10分钟 · 50题`

### MBTI 恋爱测试

快速了解你在恋爱里的性格类型和相处气质  
`10-15分钟 · 48题`

### 爱情三元论

看你更重亲密、激情还是承诺  
`3-4分钟 · 15题`

## 9. 优先级建议

如果只做最有价值的一版，优先顺序建议如下：

1. 修复名称、题量、时长不一致
2. 改入口展示方式，补充时长、作用、推荐理由
3. 调整排序和分组
4. 结果页增加“实际帮助”
5. 明示结果已影响推荐与聊天

## 10. 最终结论

这次改造不只是“美化测评入口”，而是把心理测评从附属功能升级成画像引擎。

真正需要实现的不是增加更多测评，而是把现有 5 个测评做到下面三件事：

1. 用户一眼知道该选哪个
2. 用户做完觉得真有收获
3. 系统能把结果持续用到推荐和对话里

只要这三件事成立，发现页加号里的心理测评才会从“可有可无的小功能”变成“真正推动匹配效率和用户理解自己的核心模块”。
