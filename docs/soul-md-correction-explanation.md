## 五、为什么这样修正？

### 修正前的反模式

**触发词映射表反模式**：
```markdown
| 用户说的话 | 推荐测评类型 |
|-----------|-------------|
| "性格类型" | MBTI |
| "相处节奏" | 依恋风格 |
| "性格结构" | 大五人格 |
```

虽然我用的是"可优先推荐"、"可考虑"这种软性语言，但这种"关键词 → 测评"的结构，**本质上是触发词映射表**。

**问题**：
- Agent变成关键词匹配器，失去自主判断能力
- 规则分散在多处（SOUL.md + 工具description），违反单一真相来源

---

### 修正后的正确模式

**Agent Native正确模式**：
- SOUL.md：高层原则（"可以引导做测评"、"自主选择"）
- 工具description：详细建议（单一真相来源）
- Agent：自主判断（根据上下文选择）

**优势**：
- Agent保持自主性（不是关键词匹配器）
- 规则单一真相来源（只在工具description）
- 职责边界清晰（角色定义 vs 能力描述）
