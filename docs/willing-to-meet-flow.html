关键说明

这部分用于区分“代码里已经打通的部分”和“文档定义但仍在完善的部分”。

当前已实现

  • Discovery 点击愿意认识会创建 formal subscription。
  • 会把候选人 upsert 成 recommendation 记录。
  • 会创建并 dispatch 一个 proxy intro / match case。
  • 详情页成功后引导去关系页，不直接开聊。

产品目标链路

  • 接收方B以“红娘推荐”方式看到A，而不是暴露谁先点了按钮。
  • 只有双方都点了愿意认识，才进入 chat handoff。
  • 聊天入口应该从关系页出现，而不是候选详情页。

异常分支

  • session 关闭、search run 失效、candidate 不在最新结果中都会直接失败。
  • B 拒绝会进入 declined。
  • B 超时不回复会进入 timed_out。

状态展示原则

  • 候选详情按钮只负责提交，不承载长期流程。
  • 长期状态统一在关系页展示。
  • 用户看到的是人话文案，不直接暴露底层状态名。
