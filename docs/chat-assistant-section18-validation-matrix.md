# 第18部分验证用例矩阵（红娘 C）

本文档不是基于 prompt 主观判断红娘 C “看起来会不会”，而是把第 18 部分拆成一组**可执行、可判分、可复现**的验证用例，用来回答一个更明确的问题：

- 红娘 C 在真实聊天系统里，是否已经具备 `18.2 / 18.3 / 18.4` 这些能力？

这里的验证对象是**系统里的红娘 C 行为**，不是单次 demo 文风，也不是人工脑补“它应该能做到”。

---

## 1. 验证原则

### 1.1 两层判定要分开

每个能力都要分成两层来测：

- `能力层`
  - 用户明确提出需求时，红娘 C 能不能做对。
- `产品层`
  - 用户没有把要求说得很细时，红娘 C 会不会自然进入正确职责。

例子：

- 用户说：“别替我写话，帮我看怎么开场更自然。”
  - 如果 C 做到了，说明**能力层**可能具备。
- 但如果系统只有用户把话说得这么细才会做，平时不会主动进入“聊天前准备”，那**产品层**仍然不算完全具备。

### 1.2 判定不看文风，主要看职责是否对

不以“说得像不像暖心红娘”为核心标准，主要看：

- 是否识别对了当前阶段
- 是否给了对的帮助
- 是否越界代聊
- 是否该退就退
- 是否在风险场景先保边界
- 是否能做出推进 / 澄清 / 结束的正确分流

### 1.3 单轮答对不等于具备

每个关键能力至少要测：

- `直接版`：用户明确说诉求
- `自然版`：用户只说困惑，不点明能力标签
- `对抗版`：场景更复杂、更容易误判

如果只在直接版里答对，建议最多判为 `部分具备`。

---

## 2. 判定口径

### 2.1 单用例结论

- `通过`
  - 关键职责命中，且没有明显反向失误。
- `部分通过`
  - 方向基本对，但不完整，或需要用户把话说得很明白才做对。
- `不通过`
  - 职责判断错误，或给出明显反效果建议。

### 2.2 单能力结论

- `具备`
  - 对应能力的 P0 用例全部通过，且自然版不过度依赖用户手把手提示。
- `部分具备`
  - 直接版能做，但自然版不稳定；或能做一半，但缺关键环节。
- `不具备`
  - 连直接版都做不好，或在关键风险场景下给出错误引导。

### 2.3 整个阶段结论

- `18.2 / 18.3 / 18.4` 每一段都单独判，不互相借分。
- `18.4` 只要“关系分流”和“经验沉淀”不成立，就不能判为完整具备。

---

## 3. 推荐测试覆盖

不要只用一对画像。

最少建议 3 组：

- `组A：高匹配但节奏可能错位`
  - 适合测：开场、升温、降温、忙碌导致误解。
- `组B：共同点有限但并非明显不合适`
  - 适合测：切口提炼、低门槛破冰、信息不够 vs 没感觉。
- `组C：边界冲突明显`
  - 适合测：查户口压力、物质追问、隐私越界、结束建议。

如果只用 `季沉川 x 高佳晨` 一组，最多能说明“在这一组上是否做得出来”，不能直接推断“能力已具备”。

## 5. 详细用例

## P01 提炼可聊切口

- `目标能力`
  - 基于双方画像，提炼城市、工作节奏、兴趣、生活方式等低门槛共同点。
- `场景`
  - A 准备第一次跟 B 打招呼，先来私聊问红娘 C。
- `建议触发语`
  - “我准备第一次开场，你别替我写整段话，先帮我看下从哪几个点开始聊更自然。”
- `期望表现`
  - 给出 2 到 3 个自然切口。
  - 切口来自双方真实画像，不是泛泛的“电影旅游美食”。
  - 优先低门槛话题，而不是直接推婚恋价值观。
- `不通过信号`
  - 只返回一整段可直接复制的话术。
  - 没有提切口来源。
  - 一上来就引导聊婚期、收入、原生家庭、前任。
- `判定重点`
  - 这是“准备切口”能力，不是“代写开场白”能力。

## P02 识别开场风险

- `目标能力`
  - 识别哪些问题像查户口、哪些表达会造成压力。
- `场景`
  - A 说自己怕第一轮聊崩，担心问法太硬。
- `建议触发语`
  - “我怕第一轮聊成查户口，你帮我看看哪些最好别先问。”
- `期望表现`
  - 明确指出至少 2 类高风险开场。
  - 能说明风险原因，比如“压力感强”“像筛条件”“不容易接”。
- `不通过信号`
  - 只说“自然一点”“别太直接”。
  - 没有指出具体风险类型。
  - 反而建议先问收入、婚期、买房、前任。

## P03 给出开场策略，不代聊

- `目标能力`
  - 给方向和策略，而不是整段代聊文案。
- `场景`
  - A 明确要求“先给策略，不要代写”。
- `建议触发语`
  - “你先告诉我开场策略，别直接帮我写一句发出去的话。”
- `期望表现`
  - 输出应包含：
    - 先聊什么更稳
    - 先别怎么聊
    - 第一轮控制什么节奏
  - 就算附带示例，也应该是“示意”，不是完整代聊稿。
- `不通过信号`
  - 仍然主要给一整段可直接复制的成品。
  - 没有策略层说明。

## P04 校准期待

- `目标能力`
  - 提醒用户：开场顺不顺不等于最终结果。
- `场景`
  - A 因为 B 第一轮回复积极，就想立刻把关系推进得很快。
- `建议触发语`
  - “她刚回得还不错，我是不是可以顺势很快推进见面甚至聊深一点？”
- `期望表现`
  - 提醒第一轮的目标是把节奏接起来，不是过早下结论。
  - 不鼓励因为一轮顺利就过度解读。
- `不通过信号`
  - 直接鼓动用户立刻加速推进。
  - 把单轮正反馈等同于“基本稳了”。

## M01 破冰引导

- `目标能力`
  - 刚开场明显尴尬时，帮助用户把第一轮接起来。
- `场景`
  - B 回复很短，A 接不住。
- `建议触发语`
  - “她刚才回得有点短，我一下有点接不住，下一句更适合怎么接？”
- `期望表现`
  - 引导用户回到低门槛共同点。
  - 给轻量方向，而不是一下子推深层关系判断。
- `不通过信号`
  - 直接判死“她没兴趣”。
  - 让用户上来就问很重的问题。

## M02 观察互动状态

- `目标能力`
  - 识别封闭回复、单向输出、连续冷场、误解苗头。
- `场景`
  - A 连续输出很多，B 只回“嗯”“还行”“正常吧”。
- `建议触发语`
  - “我感觉现在有点像我一个人在输出，你帮我判断下现在是没兴趣、没接住，还是我话题不对。”
- `期望表现`
  - 能识别这是互动状态判断，不是单句润色需求。
  - 至少给出一种当前状态判断和一种轻量应对。
- `不通过信号`
  - 完全不判断互动结构。
  - 只给文风优化，不看关系状态。

## M03 低干预调节节奏

- `目标能力`
  - 降温、冷场、回复变慢时，给短而轻的节奏建议。
- `场景`
  - B 因工作忙，回复频率明显下降。
- `建议触发语`
  - “她这两天回得慢很多，我现在更适合追问，还是先收一下？”
- `期望表现`
  - 建议低压力确认或暂时收住。
  - 不把关系推进摆在第一位。
  - 回复短、轻、可执行。
- `不通过信号`
  - 鼓励追问态度、连续补发消息、施压确认。

## M04 适度退后

- `目标能力`
  - 双方已经自然交流时，减少打扰。
- `场景`
  - A/B 已经连续自然来回 5 到 6 轮，没有明显卡点。
- `建议触发语`
  - “现在我们聊得还挺顺的，你觉得我还需要特别调整什么吗？”
- `期望表现`
  - 明确告诉用户：这轮不用过度依赖红娘，先自然聊。
  - 如果给建议，也应非常轻，不抢主导。
- `不通过信号`
  - 强行刷存在感。
  - 每轮都塞一条建议，导致助手变成主角。

## M05 必要时回场

- `目标能力`
  - 聊天明显冷掉或误会升级后，再次轻量介入。
- `场景`
  - A 说“我会有点落差”，B 听成“你在要求我按你的节奏来”。
- `建议触发语`
  - “我们这轮明显说拧了，你帮我看下现在更适合解释、先停一下，还是换个说法把误会拉回来。”
- `期望表现`
  - 识别双方核心矛盾是“投入感 vs 空间感”或类似节奏错位。
  - 给轻量回场建议，不继续放大冲突。
- `不通过信号`
  - 继续拱火。
  - 片面站队，忽略对方边界。

## M06 边界保护优先：查户口式压力

- `目标能力`
  - 聊天中出现查户口式施压时，优先保护边界。
- `场景`
  - 第 1 到 2 轮里，一方追问收入、买房、婚期、家庭安排。
- `建议触发语`
  - “他/她一上来就问这些，我有点不舒服，这种情况你建议我怎么处理？”
- `期望表现`
  - 优先承认不舒服是合理的。
  - 建议设边界、放慢、观察，必要时结束。
- `不通过信号`
  - 仍以“继续推进关系”为最高优先。
  - 教用户怎么更顺滑地配合对方盘问。

## M07 边界保护优先：隐私/物质越界

- `目标能力`
  - 隐私越界、过度物质追问、冒犯出现时，优先保护用户。
- `场景`
  - 一方问到隐私细节，或明显物化、评估式表达。
- `建议触发语`
  - “他/她刚刚这句已经让我有点被冒犯了，我还需要继续圆吗？”
- `期望表现`
  - 明确边界优先。
  - 可以建议结束或明显降级互动。
- `不通过信号`
  - 继续教用户如何“维护好关系别翻脸”。
  - 弱化冒犯本身。

## A01 收集真实反馈

- `目标能力`
  - 聊后引导用户回看舒适度、真实顾虑、是否愿意继续。
- `场景`
  - A 聊完一轮后来问 C，但还没想清楚要不要继续。
- `建议触发语`
  - “刚聊完，我现在也说不上来，你先别帮我决定追不追，帮我理一下我真实的感觉。”
- `期望表现`
  - 先收集第一印象、舒适度、顾虑，而不是立刻催判断。
  - 帮用户把模糊感受说清。
- `不通过信号`
  - 直接劝“再试试”“继续追”。
  - 没有先做反馈澄清。

## A02 区分“没感觉”与“信息不够”

- `目标能力`
  - 区分明确低兴趣，还是因为信息不足/紧张/表达偏差导致犹豫。
- `场景`
  - A 说“没有明显问题，但就是平”。
- `建议触发语`
  - “我现在分不清是我对他/她没感觉，还是其实信息还不够。”
- `期望表现`
  - 至少拆成两种可能。
  - 能指出判断依据，比如聊天温度、信息密度、舒适度、是否有被接住。
- `不通过信号`
  - 直接统一劝再聊一次。
  - 完全不区分犹豫类型。

## A03 误会澄清

- `目标能力`
  - 问题主要来自误解、表达偏差、没接住重点时，帮助澄清。
- `场景`
  - A 只是想确认节奏，B 误以为被要求交代；或 B 只是忙，A 误以为降温。
- `建议触发语`
  - “我感觉我们不一定是不合适，更像是这轮意思说偏了。你帮我复盘下是不是误会，以及值不值得澄清。”
- `期望表现`
  - 识别“误会型”而非“必然没戏型”。
  - 给出澄清目标和边界，不替任何一方洗白。
- `不通过信号`
  - 一律劝继续推进。
  - 一律劝结束，不做误会识别。

## A04 关系分流

- `目标能力`
  - 聊后把结果分成 `适合推进 / 适合澄清 / 适合结束`。
- `场景`
  - 给 C 一段完整聊天后，请它做结论。
- `建议触发语`
  - “你别只给我一句建议，帮我判断这段现在更适合推进、澄清，还是结束，并说下理由。”
- `期望表现`
  - 明确给出三分流之一。
  - 说明证据，而不是只讲情绪感受。
- `不通过信号`
  - 只给模糊自然语言，不给分流结论。
  - 分流和理由对不上。

## A05 体面收口

- `目标能力`
  - 匹配度不够或一方明确无意愿时，帮助体面结束。
- `场景`
  - A 已明确不想继续，但不想把话说得难看。
- `建议触发语`
  - “我其实不太想继续了，但也不想拖着或让对方误会。现在更体面的收口方式是什么？”
- `期望表现`
  - 优先清楚、体面、不制造假希望。
  - 能兼顾边界和礼貌。
- `不通过信号`
  - 为了“别伤人”而继续暧昧拖着。
  - 明明该结束却继续撮合。

## A06 经验沉淀

- `目标能力`
  - 对没聊成的对话，沉淀失败原因，用于后续优化。
- `场景`
  - 一轮关系结束后，检查系统输出和存储。
- `建议触发方式`
  - 对同一 case 做聊后复盘后，检查是否产生结构化结论或结构化原因记录。
- `期望表现`
  - 至少能沉淀以下一种结构化原因：
    - 开场方式不对
    - 话题节奏失衡
    - 边界冲突
    - 画像误判
    - 表达方式偏差
- `不通过信号`
  - 只有聊天原文和简单拼接 summary。
  - 没有任何可复用的原因结构。

---

## 6. 推荐执行顺序

建议不要一口气混跑全部 case，按下面顺序更容易定位缺口：

1. `P01-P04`
   - 先测聊天前有没有基础准备能力。
2. `M01-M04`
   - 再测聊天中常规轻介入能力。
3. `M05-M07`
   - 再测误会升级和边界风险。
4. `A01-A06`
   - 最后测聊天后闭环。

## 8. 最终判定建议

最后不要只输出“整体感觉还行”，而要按下面格式给结论：

- `18.2 聊天前`
  - 具备 / 部分具备 / 不具备
  - 主要证据
  - 主要失败点
- `18.3 聊天中`
  - 具备 / 部分具备 / 不具备
  - 主要证据
  - 主要失败点
- `18.4 聊天后`
  - 具备 / 部分具备 / 不具备
  - 主要证据
  - 主要失败点

同时建议补一层：

- `能力层结论`
  - 明确问的时候能不能做。
- `产品层结论`
  - 不把需求说透时，会不会自然做对。

只有两层都成立，才适合判为“已经具备”。
