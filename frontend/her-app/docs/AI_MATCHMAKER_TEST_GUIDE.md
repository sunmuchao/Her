# AI红娘主动提示测试指南

## 测试场景清单

### 1. 聊天前引导（opening_probe）

**如何触发**：
- 后端会自动在匹配成功后5分钟发送引导消息

**测试步骤**：
1. 打开一个新匹配的聊天页面
2. 观察聊天历史中是否有小雅的开场引导消息

**预期效果**：
```
┌─────────────────────────────┐
│ 💬 小雅的建议                │
│ "你们刚匹配成功，可以先      │
│  从共同的兴趣爱好聊起～"    │
└─────────────────────────────┘
```

---

### 2. 聊天中破冰（silence_probe）

**如何触发**：
- 后端检测到双方沉默超过5分钟会自动发送

**测试步骤**：
1. 进入聊天页面发送几条消息
2. 停止发送消息，等待5分钟
3. 刷新页面或等待轮询更新（30秒）

**预期效果**：
小雅会根据之前的对话内容给出破冰建议

---

### 3. 聊天后跟进（post_chat_followup）

**如何触发**：
- 后端会在聊天结束（双方都沉默）2小时后发送私信

**测试步骤**：
1. 聊天结束后关闭页面
2. 2小时后返回聊天页面
3. 观察私信悬浮球是否有红点提示

**预期效果**：
- 悬浮球显示未读红点
- 点击后看到小雅的私信："刚才聊得怎么样呀？"

---

## 如何验证前端改动是否生效

### 方法1：查看消息类型

打开浏览器控制台：
```javascript
// 在聊天页面打开后执行
console.log('[ChatPage] messages:', messages)
```

应该看到消息对象包含：
```javascript
{
  id: "123",
  type: "assistant",  // ← 小雅的消息
  content: "可以先聊聊周末安排～",
  source: "agent"     // ← 来自AI红娘
}
```

---

### 方法2：查看消息样式

在聊天页面中：
- 用户消息：白色背景，左右对齐
- 小雅消息：紫色背景，居中显示，带"小雅的建议"标识

---

### 方法3：查看轮询是否工作

打开控制台，等待30秒：
```javascript
// 应该看到轮询日志
[ChatPage] 轮询更新开始...
[ChatPage] 获取到新消息: 3条
```

---

## 后端触发机制（参考）

| 触发时机 | reason_code | 发送渠道 | 内容示例 |
|---------|-------------|---------|---------|
| 匹配成功后5分钟 | `opening_probe` | main_group | "你们刚匹配成功，可以先从周末安排聊起～" |
| 沉默5分钟 | `silence_probe` | main_group | "对方提到喜欢跑步，你可以问问跑多远～" |
| 聊天结束2小时 | `post_chat_followup` | assistant_dm | "刚才聊得怎么样呀？有没有需要我帮忙跟进的？" |

## 如果看不到小雅的消息

### 可能原因1：后端还没有触发
检查后端日志：
```bash
grep "opening_probe\|silence_probe\|post_chat" gateway.log
```

### 可能原因2：前端轮询未生效
检查前端代码：
```typescript
// chat-page.tsx 第430行
const interval = setInterval(async () => {
  console.log('[ChatPage] 轮询更新...')  // 添加日志
  ...
}, 30000)
```

### 可能原因3：消息类型判断错误
检查API返回数据：
```typescript
// chat-timeline.ts
console.log('[Timeline] raw messages:', timelineData.conversations)
```

确认消息包含 `source: 'agent'` 字段

## 验收标准

✅ **功能验收**：
- 聊天页面能显示小雅的主动提示消息
- 小雅消息样式明显区分于用户消息
- 30秒轮询能获取新消息

✅ **UX验收**：
- 小雅提示不打断用户聊天流程
- 用户可以选择采纳或忽略小雅的建议

✅ **架构验收**：
- 消息类型判断基于`source`字段
- timeline API作为数据来源
- 符合AI Native三层分离原则
